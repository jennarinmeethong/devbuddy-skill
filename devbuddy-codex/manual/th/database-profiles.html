ติดตั้งและย้ายระบบDatabase Profile
DevBuddy›Database Profile

Tier 2 · read-only

Database package เป็นส่วนประกอบของ Profile

database core และ engine adapter ยังอยู่ใน release แต่เลือกลง workspace composition แทนการติดตั้งเป็น host UI Plugin แยก

ทำไม adapter จึงเหมือนหายไป

Codex, Claude Code และ OpenCode จะแสดง native host adapter หลังติดตั้ง ส่วน devbuddy-database-core, devbuddy-database-mariadb และ devbuddy-database-sqlserver ไม่ใช่รายการ UI แยกของ host แต่ถูก resolve จาก data profile, เขียนลง .devbuddy/packages.json และ materialize เฉพาะ database instance ที่ workspace เลือกอย่างชัดเจน

Database Profile ที่มี

ProfilePackage ที่เลือก
data-sqlservercore, database-core, SQL Server adapter
data-postgresqlcore, database-core, PostgreSQL adapter
data-mariadbcore, database-core, MariaDB adapter
data-oraclecore, database-core, Oracle adapter
data-mongodbcore, database-core, MongoDB adapter
data-rediscore, database-core, Redis adapter

Resolve และ Materialize

เริ่มด้วย preview เสมอ การ apply profile เพียงบันทึก composition ไม่สร้าง credential และไม่ execute query จากนั้น materialize จึงสร้าง runtime แบบ self-contained read-only หนึ่งตัวสำหรับ database instance ที่ตั้งชื่อไว้

python3 scripts/profile_resolver.py profiles/data-mariadb.yaml --platform codex
python3 scripts/profile_resolver.py profiles/data-mariadb.yaml --platform codex --devbuddy-root <workspace>/.devbuddy --apply
python3 scripts/materialize_database_adapter.py --devbuddy-root <workspace>/.devbuddy --database-id billing --engine mariadb
python3 scripts/materialize_database_adapter.py --devbuddy-root <workspace>/.devbuddy --database-id billing --engine mariadb --apply
python3 scripts/register_database_adapter.py --devbuddy-root <workspace>/.devbuddy --database-id billing --engine mariadb
python3 scripts/register_database_adapter.py --devbuddy-root <workspace>/.devbuddy --database-id billing --engine mariadb --apply

การ register ก็เริ่มจาก dry-run และเพิ่ม database registry หลัง materialize เท่านั้น ตั้งค่า secret file ที่ถูก ignore ในเครื่องเอง ใช้ principal ที่มีสิทธิ์อ่านต่ำสุด และคง Tier 2 approval ตาม target ทุกครั้ง
