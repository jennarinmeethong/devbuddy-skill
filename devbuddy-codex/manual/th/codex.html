เตรียม control plane ให้พร้อม

Codex ต้องมี subagent call ที่รับทั้ง model และ effort แบบ explicit ได้ หาก capability นี้ไม่มี DevBuddy จะหยุดอย่างปลอดภัย

1. ติดตั้งอย่างปลอดภัย

ดูรายการก่อนเสมอ installer เป็น dry-run โดยค่าเริ่มต้น และปฏิเสธ collision ที่ไม่ใช่ไฟล์ DevBuddy

python3 scripts/install_codex_adapter.py
python3 scripts/install_codex_adapter.py --apply

ใช้ --codex-root <path> หากต้องการ Codex configuration root อื่นนอกจาก ~/.codex

2. ตั้งค่าโครงการ

สร้าง <project-root>/.devbuddy/settings.yaml อย่า hardcode provider model ID ใน adapter เพราะ project เป็นผู้กำหนด allowlist ที่อนุมัติ

schema_version: 1
memory_root: .devbuddy
orchestration:
  max_concurrency: 2
  task_timeout_seconds: 900
  retry_limit: 1
  approved_models:
    - id: approved-model-id
      rank: 1
      allowed_roles: [developer, qa]
      allowed_risks: [low, medium]
  approved_effort_levels:
    - id: low
      rank: 1
      allowed_roles: [developer, qa]
      allowed_risks: [low, medium]

เลือก model และ effort แยกกัน ทุกคู่ต้องอนุญาต role และ risk นั้น หากขาด budget หรือ approval งานจะเป็น waiting_user

3. สร้าง memory และตรวจสอบ

python3 scripts/init_project_memory.py --project-root <project-root> --dry-run
python3 scripts/bootstrap_knowledge.py --project-root <project-root> --dry-run
python3 scripts/validate_project_settings.py <project-root>/.devbuddy/settings.yaml
python3 scripts/validate_knowledge.py --project-root <project-root>
python3 scripts/validate_skill_metadata.py .
python3 scripts/check_adapter_conformance.py
python3 -m unittest discover tests -v

ให้รัน bootstrap แบบ dry-run เพื่อเตรียม inventory ของ repository ที่ตรวจทานได้ และใช้ --apply หลังตรวจทานแล้วเท่านั้น โดยจะเขียนเฉพาะ Context.md กับ KnowledgeBase.md ไม่เขียนทับไฟล์เดิมที่มีเนื้อหา และไม่สร้าง typed canonical entity ขึ้นเอง ตัว initializer จะวาง KnowledgeBase.md, core files อื่น, typed knowledge และ task ledger ไว้ใต้ <project-root>/.devbuddy/ โดยตรง ใช้ --root <approved-external-memory-root> --source-root <project-root> เมื่อ memory อยู่ใน external vault และตรวจด้วย python3 scripts/validate_knowledge.py --root <approved-external-memory-root>

Dispatch contract

ทุก slice ที่พร้อมส่งต้องส่งค่า model และ reasoning_effort หรือชื่อพารามิเตอร์ที่ capability ระบุแบบ explicit พร้อม task ID, role, scope, lock, risk, approved pair, timeout, retry limit, handoff และ exit condition

handoff ต้องระบุ Model / effort used หากค่าใดขาดหรือยืนยันไม่ได้ ให้ mark slice เป็น waiting_user ห้ามให้ Orchestrator ทำงานแทนหรือใช้ generic subagent

แก้ปัญหา

อาการตรวจอะไร
Skill ไม่ถูกค้นพบตรวจว่า SKILL.md และ agents/openai.yaml อยู่ใต้ skill directory ที่ติดตั้ง แล้ว refresh Codex session
งานหยุดที่ waiting_userตรวจ project settings, budget, allowlist, approval, tool และ subagent capability
ยืนยัน model หรือ effort ไม่ได้ตรวจ dispatch parameters และ handoff ค่า selection ที่ยืนยันไม่ได้ถือเป็น block
initializer ไม่ยอมทำงานตรวจ core files เดิม เพราะ initializer จะไม่เขียนทับ ให้เลือก root ใหม่หรือจัดการ conflict อย่างชัดเจน

Task memory

ใช้ $devbuddy analyze <project> เพื่อสำรวจ repository แบบ read-only แล้วเก็บที่ task-<task-id>/analysis.md Owner ต้อง reserve scope, commit ด้วย revision ปัจจุบัน แล้ว release ส่วน specialist ได้เฉพาะ task path, read keys/paths, write scope, parent revision และ handoff ที่เกี่ยวข้อง ต้องตรวจ scope ก่อนรับผล Handoff เกิน 12,000 UTF-8 bytes จะถูกปฏิเสธ และห้ามเขียน .devbuddy/ โดยตรง
