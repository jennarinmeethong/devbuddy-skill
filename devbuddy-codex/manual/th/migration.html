Upgrade · legacy removal · rollback

Migration

ย้ายทั้งการติดตั้งบน host และ layout ของ workspace อย่างปลอดภัย โดยแยก package payload ออกจาก state ของผู้ใช้และมีทางย้อนกลับ

Manual 0.4.61.x compatibilityExplicit apply

ย้ายการติดตั้งบน host

งานใหม่ควรใช้ Plugin/profile ของ host เริ่มจากรายงานแบบอ่านอย่างเดียวของ compatibility shim ทั้งสองตัว

Migration reports 
python3 devbuddy-claude/scripts/install_claude_adapter.py --migration-report
python3 devbuddy-codex/scripts/install_codex_adapter.py --migration-report

Claude Code ให้ติดตั้ง devbuddy-claude-code@devbuddy, ตรวจด้วย claude plugin list --json, ใช้ /reload-plugins และเรียก /devbuddy-claude-code:devbuddy ส่วน Codex ให้ติดตั้ง devbuddy-codex ผ่าน Plugin manager, ตรวจด้วย codex plugin list, resolve profile และเปิด thread ใหม่

ย้าย workspace layout

ใช้ initializer ที่เป็นของ package เพื่อ preview การย้าย memory และ typed folders เดิมไปใต้ knowledge-base/ โดยคง settings.yaml, tasks/ และ tools/ เป็น sibling และหยุดเมื่อปลายทางชนกัน

Preview แล้ว apply 
python3 <installed-plugin-root>/scripts/init_project_memory.py \
  --devbuddy-root /path/to/.devbuddy \
  --migrate-layout --dry-run

python3 <installed-plugin-root>/scripts/init_project_memory.py \
  --devbuddy-root /path/to/.devbuddy \
  --migrate-layout

manifest จะระบุ hash ที่เชื่อถือได้ หาก tool ถูกผู้ใช้แก้ไขจะไม่ถูก replace แบบเงียบ ๆ ต้อง review และตัดสินใจเอง

ถอน legacy skill

หลัง discovery และ read-only invocation สำเร็จ ให้ backup directory ของ legacy แล้วถอนเฉพาะไฟล์ standalone ที่รู้จัก เก็บ Plugin cache และ state ใต้ .devbuddy/ ไว้ หากต้อง rollback ให้ disable/uninstall Plugin หรือ restore backup แล้ว refresh host

อย่าใช้ recursive delete แบบกว้างresolve path ของ legacy ให้ชัดก่อน เก็บ backup และหยุดเมื่อเจอไฟล์ที่ไม่รู้จักหรือถูกแก้ไข

Backup, validation และ rollback

  1. commit หรือ copy knowledge repository ก่อน apply
  2. เก็บ dry-run output และ Plugin discovery output ใน change record
  3. apply host migration และ workspace migration แยกกัน แล้ว validate settings, knowledge, task ledger และ package hash หลังแต่ละขั้น
  4. rollback ด้วยการ disable/uninstall Plugin พร้อม keep-data หรือ restore backup ห้ามผสม generated payload เก่าและใหม่ด้วยมือ

Compatibility window

flag เดิมยังรับได้ใน DevBuddy 1.x แต่ installer ไม่ใช่ช่องทางแจกจ่ายใหม่ ประตูถอดออกใน 2.0 ต้องมีหลักฐาน clean-install, conflict, rollback, discovery และ release validation
