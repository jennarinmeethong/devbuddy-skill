Layout · tools · rollback

Migration

ย้าย memory layout เก่าและ upgrade project-local tools โดยไม่ทับไฟล์ที่ผู้ใช้แก้เอง

Manual 0.4.4ต้องสั่ง apply ชัดเจน

ย้าย layout เก่า

Preview แล้ว apply 
python3 <installed-skill>/scripts/init_project_memory.py \
  --devbuddy-root /path/to/.devbuddy --migrate-layout --dry-run
python3 <installed-skill>/scripts/init_project_memory.py \
  --devbuddy-root /path/to/.devbuddy --migrate-layout

ย้าย core files และ typed folders เข้า `knowledge-base/` แต่คง settings, tasks และ tools เป็น sibling; destination conflict จะหยุดก่อนแก้ไฟล์

Upgrade project-local tools

Preview แล้ว apply 
python3 <installed-skill>/scripts/init_project_memory.py \
  --devbuddy-root /path/to/.devbuddy --upgrade-tools --dry-run
python3 <installed-skill>/scripts/init_project_memory.py \
  --devbuddy-root /path/to/.devbuddy --upgrade-tools

Manifest ใช้ hash เดิมที่ trusted; tool ที่ถูกแก้โดยผู้ใช้จะไม่ถูก replace เงียบ ๆ

Backup และ rollback

  1. Commit/copy knowledge repository ก่อน migration
  2. เก็บ output ของ dry-run ไว้กับ change record
  3. Apply เมื่อ conflict ถูกแก้ครบ
  4. Validate settings, knowledge และ task paths
  5. Rollback ด้วย repository commit หรือ backup เดิม ไม่ผสม layout เอง

Compatibility

Legacy flags ยังใช้ได้เมื่อไม่มี ambiguity แต่ workspace ใหม่ควรใช้ `--devbuddy-root` และ `--project` ซ้ำ ไม่ควร migrate อัตโนมัติระหว่าง startup

VersioningCommit `.devbuddy/tools/manifest.json` เพื่อให้ทีมเห็น runtime version ที่ trusted
ก่อนหน้าTask และ knowledgeถัดไปแก้ปัญหา
