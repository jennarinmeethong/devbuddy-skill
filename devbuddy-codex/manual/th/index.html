เริ่มอย่างปลอดภัย

DevBuddy ส่งงานให้ specialist ตาม role และไม่ข้าม owner, approval หรือการ review ก่อนเขียน canonical knowledge.

เส้นทางที่แนะนำเริ่มที่ เริ่มต้นใช้งาน แล้วอ่าน Workspace เมื่อ FE และ BE ใช้ knowledge base ร่วมกัน

เส้นทางเอกสาร

  1. เริ่มต้นใช้งาน — ติดตั้ง, init, configure และ validate.
  2. Workspace — เลือกตำแหน่ง `.devbuddy`, ลงทะเบียน project และจัด knowledge.
  3. Scripts — อธิบาย Python ทุกตัวและขอบเขตการเขียน.
  4. Task และ knowledge — ประสานงานและ owner-controlled knowledge.
  5. Migration — ย้าย layout เก่าและ upgrade tools.
  6. แก้ปัญหา — แก้ setup/runtime errors ที่พบบ่อย.

หลักการออกแบบ

  • หลัง bootstrap runtime Python อยู่ใน workspace ของ project.
  • Knowledge ต้องมีหลักฐานและ project ID ที่ชัดเจน.
  • Dry-run, approval และ validation แสดงก่อนทุก write สำคัญ.
  • คู่มือเปิดจาก `file://` หรือ static HTTP server ได้โดยไม่ต้อง build.
