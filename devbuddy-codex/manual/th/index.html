Codex adapter · ภาพรวม

ส่งมอบซอฟต์แวร์อย่างเป็นระบบ

DevBuddy คือ control plane สำหรับ Codex ที่ช่วยจัดลำดับงาน มอบหมาย role เฉพาะทาง ขออนุมัติ และเก็บหลักฐานในทุก handoff

เริ่มจาก preview installer, สร้าง project settings, ตรวจ validation แล้วจึง dispatch

เริ่มต้นอย่างรวดเร็ว

  1. ดูรายการไฟล์ก่อนด้วย python3 scripts/install_codex_adapter.py
  2. สร้าง <project-root>/.devbuddy/settings.yaml พร้อม model และ effort allowlist ที่ user อนุมัติ
  3. ตรวจ skill และ project settings ก่อน dispatch ครั้งแรก
  4. เรียก $devbuddy <task> โดยให้ Orchestrator เลือกกราฟ role
python3 scripts/install_codex_adapter.py
python3 scripts/validate_skill_metadata.py .
python3 scripts/check_adapter_conformance.py
python3 -m unittest discover tests -v
$devbuddy <task>

ความต่างของ Codex adapter

เรื่องพฤติกรรม
Roleมี role profile เดียวต่อบทบาท และแยก role ออกจาก effort
Modelส่งต่อครั้งจาก allowlist ของ project settings
Effortส่งต่อครั้งด้วย reasoning_effort หรือชื่อพารามิเตอร์ตาม capability ที่ตรวจพบ
การตรวจสอบhandoff ต้องรายงานคู่ model/effort ไม่เช่นนั้น slice จะถือว่ายังยืนยันไม่ได้

Memory ที่ค้นหาได้ง่าย

ค่าเริ่มต้นคือ <project-root>/.devbuddy/ ซึ่งเก็บ settings.yaml, KnowledgeBase.md, core memory อีกสามไฟล์, typed knowledge และ task ledger ใน root เดียวกัน ใช้ python3 scripts/bootstrap_knowledge.py --project-root <project-root> --dry-run เพื่อเตรียม inventory ของ repository ที่ตรวจทานได้ และใช้ --apply หลังตรวจทานแล้วเท่านั้น โดยจะเขียนเฉพาะ Context.md กับ KnowledgeBase.md ไม่เขียนทับไฟล์เดิมที่มีเนื้อหา และไม่สร้าง typed canonical entity เอง ส่วน memory_root ภายนอกจะถูกใช้ตรงตาม path ที่กำหนด
