Install · workspace · first task

เริ่มต้นใช้งาน

ติดตั้ง Plugin หรือ profile ของ host, สร้าง multi-project workspace, ตรวจ runtime ในเครื่อง และเริ่ม task แรกแบบมีขอบเขต

Manual 0.4.6Plugin 1.0.1เริ่มจาก dry-run

สิ่งที่ต้องมี

ใช้ Python 3.9 ขึ้นไปสำหรับ workspace scripts, host ที่รองรับและ login แล้ว, รวมถึงสิทธิ์อ่าน workspace กับทุก repository ที่จะลงทะเบียน หากมี knowledge repository แยกควร backup และใช้ version control

ติดตั้ง package ของ host

การติดตั้งใหม่ใช้ Plugin/profile แบบ native ของ host เพียงหนึ่งตัว อ่าน คู่มือ Plugin-first สำหรับ lifecycle และ วิธีแก้รายการว่าง อย่าติดตั้ง devbuddy-core หรือ standalone skill แยกต่างหาก

Codex — ใช้ marketplace source จากผู้เผยแพร่ 
codex plugin marketplace list --json
codex plugin marketplace add . --json
codex plugin list --available --json
codex plugin add devbuddy-codex@devbuddy --json
codex plugin list --json
python3 scripts/profile_resolver.py profiles/codex.yaml --platform codex --dry-run
# เปิด Codex thread ใหม่ แล้วจึง
$devbuddy <task>
ขอบเขต legacyinstaller เดิมเป็น migration-aware shim สำหรับ DevBuddy 1.x จะแสดง Plugin path เป็นค่าเริ่มต้น และไม่ลบหรือทับไฟล์ host

สร้าง workspace

เลือกตำแหน่ง .devbuddy ที่อนุมัติแล้ว ใช้ initializer ที่อยู่ใน package/profile ที่ติดตั้ง โดย placeholder ด้านล่างหมายถึง path ของ package นั้น และใช้ --project ID=PATH ซ้ำสำหรับ FE, BE, mobile, service หรือ repository อื่น

Preview แล้ว apply 
python3 <installed-plugin-root>/scripts/init_project_memory.py \
  --devbuddy-root /path/to/knowledge-repo/.devbuddy \
  --project fe=../frontend \
  --project be=../backend \
  --dry-run

python3 <installed-plugin-root>/scripts/init_project_memory.py \
  --devbuddy-root /path/to/knowledge-repo/.devbuddy \
  --project fe=../frontend \
  --project be=../backend

relative path จะ resolve จาก parent ของ .devbuddy และต้องมีอยู่ ไม่ซ้ำหลัง resolve และอยู่นอก control directory

ตั้งค่า settings

initializer จะสร้าง project registry, memory locator และ model/effort default ของ provider ให้ครบและมี version จากนั้นจำกัด approval boundary ก่อน dispatch โดย host selection อยู่ใน profile ที่ติดตั้ง

settings.yaml 
schema_version: 1
settings_version: 0.4.6
workspace:
  projects:
    fe:
      path: ../frontend
    be:
      path: ../backend
memory_root: knowledge-base
orchestration:
  max_concurrency: 2
  task_timeout_seconds: 900
  retry_limit: 1
  adapter_profiles: [claude, codex]
  approved_models: [...] # ชื่อที่ host อนุมัติ
  approved_effort_levels: [...] # ค่า default เรียงลำดับ
tools:
  is_rtk: false

ถ้า settings_version ต่างกัน ให้ preview แล้วรัน init_project_memory.py --upgrade-settings ซึ่งเติมเฉพาะ default ที่ขาด ไม่ทับค่าที่มี ตั้ง tools.is_rtk: true ต่อเมื่อมี RTK ใน PATH เท่านั้น; คำสั่งที่ไม่รองรับยังรันตรง

ตรวจและ bootstrap

Project-local tools 
python3 .devbuddy/tools/validate_project_settings.py .devbuddy/settings.yaml
python3 .devbuddy/tools/bootstrap_knowledge.py --devbuddy-root .devbuddy --project-id fe --dry-run
python3 .devbuddy/tools/bootstrap_knowledge.py --devbuddy-root .devbuddy --project-id fe --apply
python3 .devbuddy/tools/validate_knowledge.py --devbuddy-root .devbuddy

ทำซ้ำกับ be และ review observation ก่อน apply; bootstrap เขียนเฉพาะไฟล์ observation ที่มี label และไม่สร้าง typed canonical entity เอง

สร้าง task แรก

Workspace task 
python3 .devbuddy/tools/task_memory.py init \
  --devbuddy-root .devbuddy \
  --project-id fe --project-id be \
  --task-id checkout-001

ใช้ ledger เดียวสำหรับงานข้าม repository แล้วอ่าน Task และ knowledge ต่อเพื่อ reserve project-qualified scope และส่งต่อ evidence
