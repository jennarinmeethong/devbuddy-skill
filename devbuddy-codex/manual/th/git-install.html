ติดตั้ง Profile และ Migration

ติดตั้ง Plugin ของ host จาก Git tag หรือ commit SHA ที่อนุมัติ และเก็บ standalone skill เก่าไว้เพียงช่วงที่ต้อง migration เท่านั้น

ติดตั้งหรืออัปเดต Host Plugin

แทน v1.0.2 ด้วย tag หรือ commit SHA ที่อนุมัติ และใช้คำสั่งเดิมเมื่อต้องอัปเดต Claude Code ต้องสั่ง /reload-plugins; Codex ต้องเปิด task ใหม่; OpenCode ใช้ package จาก Git subdirectory

# Codex
codex plugin marketplace add jennarinmeethong/devbuddy-skill --ref v1.0.2 --json
codex plugin add devbuddy-codex@devbuddy --json

# Claude Code
claude plugin marketplace add jennarinmeethong/devbuddy-skill@v1.0.2 --scope user --sparse .claude-plugin plugin/devbuddy-claude-code
claude plugin install devbuddy-claude-code@devbuddy --scope user

# OpenCode
opencode plugin 'github:jennarinmeethong/devbuddy-skill#v1.0.2::path:plugin/devbuddy-core/opencode' --global

Profile และความสามารถ

Profileสิ่งที่เปิดใช้
minimalเฉพาะ DevBuddy core แบบ portable
software-deliveryCore พร้อม policy ด้าน security สำหรับงานส่งมอบซอฟต์แวร์
full-engineeringCore, security, documents, browser, deployment, project-management และ policy database core
codex, claude-code, opencodeHost adapter native ของแต่ละ platform
data-sqlserver, data-postgresql, data-mariadb, data-oracle, data-mongodb, data-redisCore พร้อม adapter ฐานข้อมูลแบบอ่านอย่างเดียว Tier 2 หนึ่ง engine ยังต้อง materialize, ตั้ง secret ในเครื่อง, ใช้สิทธิ์ต่ำสุด และขอ approval ตาม target
python3 scripts/profile_resolver.py profiles/software-delivery.yaml --platform codex
python3 scripts/profile_resolver.py profiles/data-postgresql.yaml --platform claude-code
python3 scripts/profile_resolver.py profiles/data-postgresql.yaml --platform claude-code --devbuddy-root <workspace>/.devbuddy --apply

ตัว resolver เป็น dry-run โดยปริยายและไม่ overwrite composition เดิม

Materialize Database Adapter

clone release เดียวกัน ตัว materializer สร้าง executable แบบ self-contained และเขียนเฉพาะ manifest กับ template ที่ไม่มี secret ใต้ .devbuddy/tools/databases/<database-id> โดยไม่อ่านหรือสร้าง credential

git clone --depth 1 --branch v1.0.2 https://github.com/jennarinmeethong/devbuddy-skill.git devbuddy-release
python3 devbuddy-release/scripts/workspace.py init --devbuddy-root <workspace>/.devbuddy --apply
python3 devbuddy-release/scripts/materialize_database_adapter.py --devbuddy-root <workspace>/.devbuddy --database-id billing --engine postgresql
python3 devbuddy-release/scripts/materialize_database_adapter.py --devbuddy-root <workspace>/.devbuddy --database-id billing --engine postgresql --apply

เก็บ standalone skill เก่า

ทำหลัง Plugin ถูกติดตั้งและถูก discover แล้วเท่านั้น ให้ preview ก่อน คำสั่งจะย้ายเฉพาะไฟล์ DevBuddy ที่รู้จักไปยัง backup ตามเวลา ไม่ลบไฟล์ผู้ใช้และไม่ถอน Plugin

# Codex legacy skill
python3 devbuddy-release/scripts/retire_legacy_host_skill.py --host codex
python3 devbuddy-release/scripts/retire_legacy_host_skill.py --host codex --apply

# Claude Code legacy skill และ DevBuddy agents
python3 devbuddy-release/scripts/retire_legacy_host_skill.py --host claude-code
python3 devbuddy-release/scripts/retire_legacy_host_skill.py --host claude-code --apply

ย้ายเอกสารจาก workspace เก่า

ใช้คำสั่งที่สงวนไว้: Codex คือ $devbuddy migrate <workspace> และ Claude Code คือ /devbuddy-claude-code:devbuddy migrate <workspace> คำสั่งจะ inventory เอกสารเก่าก่อนและเสนอ mapping โดยเก็บเอกสารเดิมไว้เป็น evidence และต้องขอ approval ก่อนสร้าง typed document ใหม่ หากไม่ได้เรียกผ่าน host ให้ใช้ report แบบ read-only เดียวกัน การย้ายโครงสร้างเป็นคนละขั้นและเริ่มจาก dry-run:

python3 <installed-plugin-root>/scripts/migration_report.py --devbuddy-root <workspace>/.devbuddy
python3 devbuddy-release/scripts/migrate_legacy_database_tools.py --devbuddy-root <workspace>/.devbuddy
python3 <installed-plugin-root>/scripts/init_project_memory.py --devbuddy-root <workspace>/.devbuddy --migrate-layout --dry-run

# apply แต่ละงานที่อนุมัติแล้วแยกกัน
python3 devbuddy-release/scripts/migrate_legacy_database_tools.py --devbuddy-root <workspace>/.devbuddy --apply
python3 <installed-plugin-root>/scripts/init_project_memory.py --devbuddy-root <workspace>/.devbuddy --migrate-layout

ห้ามผสม payload เก่ากับ generated payload เอง และต้อง validate settings, knowledge และ host Plugin หลัง apply ทุกขั้น

Key สำหรับ Typed Document ใหม่

คง key เดิมไว้ สำหรับเอกสารใหม่ทุกชนิด รวมถึง incident และ business rule ให้ใช้ตัว generator ของ Plugin แทน counter ในเครื่อง:

python3 <installed-plugin-root>/scripts/new_knowledge_key.py --prefix INC
python3 <installed-plugin-root>/scripts/new_knowledge_key.py --prefix BR

key ประกอบด้วย prefix, UTC timestamp และ UUID4 จึงสร้างจากคนละเครื่องได้โดยไม่ชนกัน

ตรวจสอบ

python3 scripts/profile_resolver.py profiles/codex.yaml --platform codex
python3 <workspace>/.devbuddy/tools/validate_project_settings.py <workspace>/.devbuddy/settings.yaml
python3 <workspace>/.devbuddy/tools/validate_knowledge.py --devbuddy-root <workspace>/.devbuddy
