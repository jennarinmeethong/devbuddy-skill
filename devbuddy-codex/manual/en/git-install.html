Install, profiles, and migration

Install a host Plugin from an approved Git tag or commit SHA. Keep the legacy standalone skill only long enough to migrate.

Install or update a host Plugin

Replace v1.0.2 with an approved tag or full commit SHA. Re-run the same command when updating. Claude Code needs /reload-plugins; Codex needs a new task; OpenCode reads the Git subdirectory package.

# Codex
codex plugin marketplace add jennarinmeethong/devbuddy-skill --ref v1.0.2 --json
codex plugin add devbuddy-codex@devbuddy --json

# Claude Code
claude plugin marketplace add jennarinmeethong/devbuddy-skill@v1.0.2 --scope user --sparse .claude-plugin plugin/devbuddy-claude-code
claude plugin install devbuddy-claude-code@devbuddy --scope user

# OpenCode
opencode plugin 'github:jennarinmeethong/devbuddy-skill#v1.0.2::path:plugin/devbuddy-core/opencode' --global

Profiles and capabilities

ProfileWhat it enables
minimalPortable DevBuddy core only.
software-deliveryCore plus security delivery policy.
full-engineeringCore, security, documents, browser, deployment, project-management, and database core policy.
codex, claude-code, opencodeThe native host adapter for that platform.
data-sqlserver, data-postgresql, data-mariadb, data-oracle, data-mongodb, data-redisCore plus one read-only, Tier 2 database engine adapter. It still needs materialization, a local secret file, least-privilege access, and target approval.
python3 scripts/profile_resolver.py profiles/software-delivery.yaml --platform codex
python3 scripts/profile_resolver.py profiles/data-postgresql.yaml --platform claude-code
python3 scripts/profile_resolver.py profiles/data-postgresql.yaml --platform claude-code --devbuddy-root <workspace>/.devbuddy --apply

The resolver is dry-run by default and refuses to overwrite an existing composition.

Materialize a database adapter

Clone the same approved release. The materializer compiles a self-contained executable and writes only a manifest and non-secret template below .devbuddy/tools/databases/<database-id>; it never reads or creates credentials.

git clone --depth 1 --branch v1.0.2 https://github.com/jennarinmeethong/devbuddy-skill.git devbuddy-release
python3 devbuddy-release/scripts/workspace.py init --devbuddy-root <workspace>/.devbuddy --apply
python3 devbuddy-release/scripts/materialize_database_adapter.py --devbuddy-root <workspace>/.devbuddy --database-id billing --engine postgresql
python3 devbuddy-release/scripts/materialize_database_adapter.py --devbuddy-root <workspace>/.devbuddy --database-id billing --engine postgresql --apply

Retire an old standalone skill

Do this only after the Plugin is installed and discovered. Preview first. The command moves only recognized DevBuddy files to a timestamped backup; it does not delete user files or uninstall the Plugin.

# Codex legacy skill
python3 devbuddy-release/scripts/retire_legacy_host_skill.py --host codex
python3 devbuddy-release/scripts/retire_legacy_host_skill.py --host codex --apply

# Claude Code legacy skill and DevBuddy agents
python3 devbuddy-release/scripts/retire_legacy_host_skill.py --host claude-code
python3 devbuddy-release/scripts/retire_legacy_host_skill.py --host claude-code --apply

Migrate legacy workspace documents

Use the reserved host command: $devbuddy migrate <workspace> in Codex or /devbuddy-claude-code:devbuddy migrate <workspace> in Claude Code. It first inventories legacy documents and presents a mapping; it preserves old documents as evidence and requires approval before creating typed replacements. Structural operations stay separate and dry-run-first:

python3 devbuddy-release/scripts/migrate_legacy_database_tools.py --devbuddy-root <workspace>/.devbuddy
python3 <installed-plugin-root>/scripts/init_project_memory.py --devbuddy-root <workspace>/.devbuddy --migrate-layout --dry-run

# Apply each approved operation separately
python3 devbuddy-release/scripts/migrate_legacy_database_tools.py --devbuddy-root <workspace>/.devbuddy --apply
python3 <installed-plugin-root>/scripts/init_project_memory.py --devbuddy-root <workspace>/.devbuddy --migrate-layout

Never mix old and generated payloads manually. Validate settings, knowledge, and the host Plugin after every applied step.

Keys for new typed documents

Keep existing keys unchanged. For every new document—including incidents and business rules—use the Plugin generator, not a local sequential counter:

python3 <installed-plugin-root>/scripts/new_knowledge_key.py --prefix INC
python3 <installed-plugin-root>/scripts/new_knowledge_key.py --prefix BR

Keys combine the prefix, UTC timestamp, and UUID4 entropy, so contributors on different machines can create documents without key collisions.
