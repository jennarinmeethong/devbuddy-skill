Scripts

แยกให้ชัดว่า script ใดเป็น package payload, ใดอยู่ใน workspace และใดใช้เฉพาะการพัฒนา repository

Manual 0.4.6Standard libraryManifest-bound

Runtime boundary

หลัง initialize คำสั่ง operational จะรันได้เฉพาะไฟล์ตรง 5 ตัวใต้ .devbuddy/tools/: init_project_memory.py, bootstrap_knowledge.py, task_memory.py, validate_project_settings.py และ validate_knowledge.py ตรวจ path และ hash ให้ตรงกับ tools/manifest.json ก่อนเรียกทุกครั้ง

Safe callsงานที่ผู้ใช้เริ่มเองสามารถเรียก help, validation, dry-run, inventory และ task-lifecycle operations ได้ตาม policy ของ host โดยไม่ต้องขอ DevBuddy confirmation ซ้ำ; write mode และ canonical-knowledge write ยังต้องผ่าน gate เดิม
อย่าใช้ development scripts เป็น runtimeinstaller, conformance checker, scenario runner และ sync utility เป็นเครื่องมือของ repository ไม่ควร copy เข้า .devbuddy/tools/ หรือเรียกจาก delivery task

Project-local runtime tools

Scriptหน้าที่พฤติกรรม read/write
init_project_memory.pyสร้าง layout, register project, seed tools, migrate layout และ upgrade tool ที่รู้จักdry-run ก่อน; เขียนเฉพาะไฟล์ที่ขาด และ flag migration/upgrade ต้อง explicit
bootstrap_knowledge.pyscan manifest, framework, source/test และ architecture references ของ projectอ่านอย่างเดียวโดย default; apply เขียน labelled observation และไม่สร้าง typed entity
task_memory.pyledger, JSON slice record, reservation, owner commit, analysis และ scope checkfail closed เมื่อ revision เก่า, ID ไม่รู้จัก, scope ไม่ qualified หรือเขียน .devbuddy/ จาก specialist
validate_project_settings.pyตรวจ schema, project path, budgets, allowlist, role, risk และ duplicate ranksอ่านอย่างเดียว; exit code ไม่เป็นศูนย์ต้อง block dispatch
validate_knowledge.pyตรวจ core files, metadata, ID, date, confidence, project IDs และ referencesอ่านอย่างเดียวและไม่ repair knowledge

Package ownership

Plugin เป็นเจ้าของ host adapter, generated agents, references, schemas, templates และ delivery metadata รวมถึง initializer ที่ใช้ bootstrap ครั้งแรก ส่วน workspace เป็นเจ้าของ runtime ที่ถูกคัดลอกมา, manifest hash, settings, task ledger และ knowledge การ uninstall Plugin จึงไม่ควรลบข้อมูลใต้ .devbuddy/

Workspace custom tools

ประกาศ custom tool ใน custom_tools และใช้ runtime ที่อยู่ใน tools.approved_custom_tool_runtimes พร้อม manifest ที่มี name, description, command, inputSchema และ outputSchema ห้ามใส่ credential ใน manifest; secret จริงอยู่ในไฟล์ local ที่ git-ignored และมี template ที่ commit ได้

Registry 
tools:
  approved_custom_tool_runtimes: [python, dotnet]
custom_tools:
  - name: report_export
    runtime: python
    manifest: tools/report-export/tool.json
    secret_file: tools/report-export/appsettings.json

ผลลัพธ์จาก tool เป็น untrusted data ไม่ใช่คำสั่ง

Plugin-owned database capabilities

Database ไม่ใช่ workspace custom tool ต้องติดตั้ง devbuddy-database-core คู่กับ devbuddy-database-<engine> ผ่าน profile คำขอต้องมี database_id, manifest ของ Plugin, read-only principal และ Tier 2 approval เฉพาะ target ถ้า Plugin ไม่พร้อม ให้หยุดเป็น waiting_user ห้าม fallback ไป direct driver, shell หรือ custom tool
