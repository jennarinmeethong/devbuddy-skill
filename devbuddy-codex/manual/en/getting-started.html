Getting started

Install an adapter, create a multi-project workspace, seed local runtime tools, and make the first validation pass.

Manual 0.4.5Dry-run first

Prerequisites

Use Python 3.9 or newer, an approved configuration root for the adapter you are installing, and filesystem access to the workspace plus every registered repository. A dedicated knowledge repository should be backed up and versioned.

Install the adapter

Preview the installer before applying it. It copies skill metadata and templates and refuses unrelated collisions.

Codex 
python3 devbuddy-codex/scripts/install_codex_adapter.py
python3 devbuddy-codex/scripts/install_codex_adapter.py --apply
Runtime boundaryThe installed skill keeps only the global initializer as executable Python. Runtime tools are copied to .devbuddy/tools/.

Initialize the workspace

Choose any approved `.devbuddy` location. Repeat `--project ID=PATH` for FE, BE, mobile, services or other repositories.

Preview then apply 
python3 <installed-skill>/scripts/init_project_memory.py \
  --devbuddy-root /path/to/knowledge-repo/.devbuddy \
  --project fe=../frontend \
  --project be=../backend \
  --dry-run

python3 <installed-skill>/scripts/init_project_memory.py \
  --devbuddy-root /path/to/knowledge-repo/.devbuddy \
  --project fe=../frontend \
  --project be=../backend

Relative paths resolve from the parent of `.devbuddy`. Paths must exist, be unique and stay outside `.devbuddy`.

Configure settings

The initializer creates a complete, versioned workspace registry, memory locator, and provider-specific model/effort defaults. Narrow the approval boundary for your project before dispatch.

settings.yaml 
schema_version: 1
settings_version: 0.4.5
workspace:
  projects:
    fe:
      path: ../frontend
    be:
      path: ../backend
memory_root: knowledge-base
orchestration:
  max_concurrency: 2
  task_timeout_seconds: 900
  retry_limit: 1
  adapter_profiles: [claude, codex]
  approved_models: [...] # Claude: Haiku/Sonnet/Opus/Fable; Codex: Luna/Terra/Sol
  approved_effort_levels: [...] # provider-specific ranked defaults
tools:
  is_rtk: false

Claude and Codex select entries tagged for the adapter currently running; there is no active-adapter toggle. When settings_version differs, preview and run init_project_memory.py --upgrade-settings; it fills only missing defaults and never overwrites existing values. Set tools.is_rtk to true only when rtk is available on PATH; DevBuddy then uses supported RTK command equivalents, such as git status -> rtk git status and rg -> rtk grep, while unsupported commands remain direct.

Validate and bootstrap

Project-local tools 
python3 .devbuddy/tools/validate_project_settings.py .devbuddy/settings.yaml
python3 .devbuddy/tools/bootstrap_knowledge.py --devbuddy-root .devbuddy --project-id fe --dry-run
python3 .devbuddy/tools/bootstrap_knowledge.py --devbuddy-root .devbuddy --project-id fe --apply
python3 .devbuddy/tools/validate_knowledge.py --devbuddy-root .devbuddy

Repeat bootstrap for `be`. Review observations before applying; bootstrap never creates typed canonical entities.

Create the first task

Workspace task 
python3 .devbuddy/tools/task_memory.py init \
  --devbuddy-root .devbuddy \
  --project-id fe --project-id be \
  --task-id checkout-001

Use one ledger for cross-repository work. Continue with Tasks & knowledge to reserve project-qualified scopes.
