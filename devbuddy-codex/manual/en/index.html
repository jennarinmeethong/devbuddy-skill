Start with the current distribution

Install one host-native Plugin or profile, then invoke the explicit adapter entrypoint. The portable devbuddy-core policy is bundled as a dependency; a second standalone skill is not required.

Recommended pathRead Plugin-first, continue with Getting started, then open the Workspace guide for multi-repository work.

Documentation path

  1. Plugin-first — package IDs, marketplace/profile lifecycle, migration, and ownership.
  2. Getting started — install, initialize, configure, validate, and create a task.
  3. Workspace — choose .devbuddy, register projects, and organize knowledge.
  4. Scripts — understand package-owned and project-local runtimes.
  5. Tasks & knowledge — coordinate tasks and owner-controlled knowledge.
  6. Migration — move old layouts and upgrade tools safely.
  7. Troubleshooting — resolve Plugin, workspace, and runtime errors.

Design principles

  • Plugins own host payloads; .devbuddy/ owns workspace state.
  • Runtime Python runs from the project-local tools whose manifest hash is verified.
  • Knowledge is explicit, evidence-backed, and scoped to project IDs.
  • Dry-run, approval, and validation gates appear before writes.
  • Specialists cannot silently replace the owner, bypass approvals, or write canonical knowledge from an unreviewed scan.
