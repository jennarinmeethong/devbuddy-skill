Diagnostics · safe recovery

Troubleshooting

Resolve Plugin, workspace, and runtime failures while preserving user files and the audit trail.

Manual 0.4.6Fail closedKeep data

Plugin is missing or not discoverable

First distinguish marketplaces (configured sources) from Plugins (available or installed packages). An empty Plugin list is usually a missing, stale, or wrong marketplace source—not a reason to reinstall the legacy skill.

claude plugin marketplace list
claude plugin list --json
# or, on Codex
codex plugin marketplace list --json
codex plugin list --available --json

For Claude Code, run /reload-plugins after install/update and invoke /devbuddy-claude-code:devbuddy. For Codex, start a new thread after install/update. Do not install the legacy bare skill to fix a namespaced Plugin.

The Plugin list is empty or the package is not found

Work through the matching host path below. Preserve the package ID, marketplace name, and installation scope exactly. Stop if the source is not one approved by your team; a guessed source can install the wrong package.

Claude Code

  1. Confirm the repository has .claude-plugin/marketplace.json, validate the package, and list marketplaces.
  2. If devbuddy is missing, add the approved source using the same scope as the Plugin.
  3. Install the exact selector and scope, list it, then reload the session.
claude plugin validate plugin/devbuddy-claude-code
claude plugin marketplace list
claude plugin marketplace add . --scope user
claude plugin install devbuddy-claude-code@devbuddy --scope user --yes
claude plugin list --json
# in Claude Code
/reload-plugins
/devbuddy-claude-code:devbuddy <task>

If the package is still absent, close and reopen Claude Code; verify that the marketplace path is readable and that its scope matches the install scope. If the Plugin appears but the command does not, reload once more and use its full namespace. Do not fall back to /devbuddy; that is the legacy standalone command.

Codex

  1. For this repository, add the repository root: its catalog is .agents/plugins/marketplace.json.
  2. List available packages and confirm devbuddy-codex@devbuddy.
  3. Install it, verify installed/enabled JSON, resolve the profile, and start a new thread.
codex plugin marketplace list --json
codex plugin marketplace add . --json
codex plugin marketplace list --json
codex plugin list --available --json
codex plugin add devbuddy-codex@devbuddy --json
codex plugin list --json
python3 scripts/profile_resolver.py profiles/codex.yaml --platform codex --dry-run
# in a new Codex thread
$devbuddy <task>

If the marketplace is listed but the package is absent, confirm the catalog still points to ./plugins/devbuddy-codex and that its manifest exists. A local clone reflects source changes directly; upgrade only a marketplace that was added as a Git source: codex plugin marketplace upgrade <marketplace>. If installation fails with an unknown selector, run codex plugin marketplace list --json and use the displayed marketplace name. If the Plugin is installed but $devbuddy is absent, open a new thread; then check the profile dry-run before applying workspace changes.

Entrypoint does not work

Use the host-native explicit command: Claude Code uses /devbuddy-claude-code:devbuddy; Codex uses $devbuddy. The bare Claude /devbuddy name is only for the legacy standalone compatibility window.

Migration or uninstall is unclear

Run the compatibility shim in report-only mode. It should describe the Plugin path without modifying host files:

python3 devbuddy-claude/scripts/install_claude_adapter.py --migration-report
python3 devbuddy-codex/scripts/install_codex_adapter.py --migration-report

Back up exact legacy paths before removal. Use Claude's --keep-data uninstall option for Plugin rollback and never remove .devbuddy/.

Installer or initializer reports a collision

Choose a different configuration root or inspect the target file. Installers and migration shims replace only recognized DevBuddy artifacts and refuse unrelated or unknown files.

The initializer rejects a project

Check that the path exists, is unique after resolution, and is outside .devbuddy. Relative paths resolve from the parent of the selected workspace root.

Settings validation fails

Confirm memory_root: knowledge-base, at least one project entry, existing project paths, unique model/effort ranks, budgets, and allowed roles/risks.

Validate settings 
python3 .devbuddy/tools/validate_project_settings.py .devbuddy/settings.yaml

Tool upgrade is blocked

The current file differs from the manifest hash. Review the diff and restore the trusted version or handle the project-local change explicitly; never force-replace an unknown file.

Bootstrap refuses to apply

An observation for that project may already exist, or the target file is not scaffoldable. Review the existing section and promote approved facts through the owner protocol.

Runtime or antivirus warning

Confirm commands use .devbuddy/tools/ and the package initializer is the only bootstrap entrypoint. Keep project-local tools committed in a workspace repository whose execution location is transparent to scanners.

EvidenceCapture the warning, command, and path in task evidence. Do not disable a scanner or bypass quarantine.

Validation checklist

  • Validate the Plugin manifest and host discovery.
  • If the list is empty, re-add the marketplace/package using the recovery steps above.
  • Refresh Claude or start a new Codex thread.
  • Validate settings, knowledge, and task ledger.
  • Review manifest hashes and project-qualified scopes.
  • Record evidence and rollback data.
