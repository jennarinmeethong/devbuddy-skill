Setup · validation · troubleshooting

Ready the control plane.

Codex must expose a subagent call that accepts both an explicit model and an effort parameter. If it cannot, DevBuddy blocks safely.

1. Install safely

Preview first. The installer is dry-run by default and refuses non-DevBuddy collisions.

python3 scripts/install_codex_adapter.py
python3 scripts/install_codex_adapter.py --apply

Use --codex-root <path> for an approved Codex configuration root other than ~/.codex.

2. Configure the project

Create <project-root>/.devbuddy/settings.yaml. Do not hardcode provider model IDs in the adapter; the project owns its approved allowlist.

schema_version: 1
memory_root: .devbuddy
orchestration:
  max_concurrency: 2
  task_timeout_seconds: 900
  retry_limit: 1
  approved_models:
    - id: approved-model-id
      rank: 1
      allowed_roles: [developer, qa]
      allowed_risks: [low, medium]
  approved_effort_levels:
    - id: low
      rank: 1
      allowed_roles: [developer, qa]
      allowed_risks: [low, medium]

Choose model and effort independently. Every selected pair must permit the assigned role and risk. Missing budgets or approvals produce waiting_user.

3. Initialise memory and validate

python3 scripts/init_project_memory.py --project-root <project-root> --dry-run
python3 scripts/bootstrap_knowledge.py --project-root <project-root> --dry-run
python3 scripts/validate_project_settings.py <project-root>/.devbuddy/settings.yaml
python3 scripts/validate_knowledge.py --project-root <project-root>
python3 scripts/validate_skill_metadata.py .
python3 scripts/check_adapter_conformance.py
python3 -m unittest discover tests -v

Run bootstrap in dry-run mode to prepare a reviewable repository inventory. Use --apply only after review; it writes only Context.md and KnowledgeBase.md, never overwrites non-empty existing files, and never invents typed canonical entities. The initializer places KnowledgeBase.md, the other core files, typed knowledge, and task ledgers directly under <project-root>/.devbuddy/. For an external vault, use --root <approved-external-memory-root> --source-root <project-root> and validate it with python3 scripts/validate_knowledge.py --root <approved-external-memory-root>.

Dispatch contract

For every ready slice, pass the selected model and reasoning_effort (or documented equivalent) explicitly. Include the task ID, role, scope, lock, risk, approved pair, timeout, retry limit, required handoff, and exit condition.

The handoff must state Model / effort used. If either value is omitted or cannot be verified, mark the slice waiting_user; never substitute the Orchestrator or a generic subagent.

Troubleshooting

SymptomWhat to check
Skill is not discoveredConfirm SKILL.md and agents/openai.yaml are under the installed skill directory, then refresh the Codex session.
Task stops at waiting_userValidate project settings; check budget, allowlist, approval, tool, and subagent capability gates.
Model or effort is unverifiedCheck the dispatch parameters and handoff field. Unverified selection is a block, not a success.
Memory initializer refuses to runReview existing core files. It will not overwrite them; choose a new approved root or handle the conflict explicitly.
