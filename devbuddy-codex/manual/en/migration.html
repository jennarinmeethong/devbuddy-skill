Migration

Move both host distribution and workspace layout safely. Keep package payloads separate from user-owned state and preserve a reversible path.

Manual 0.4.61.x compatibilityExplicit apply

Migrate the host installation

New work should use the host Plugin/profile. Start with read-only reports from both compatibility shims:

Migration reports 
python3 devbuddy-claude/scripts/install_claude_adapter.py --migration-report
python3 devbuddy-codex/scripts/install_codex_adapter.py --migration-report

For Claude Code, install devbuddy-claude-code@devbuddy, verify with claude plugin list --json, run /reload-plugins, and invoke /devbuddy-claude-code:devbuddy. For Codex, install devbuddy-codex through the host Plugin manager, verify with codex plugin list, resolve the profile, and start a new thread.

Migrate the workspace layout

Use the package-owned initializer to preview the move of legacy memory and typed folders into knowledge-base/. It keeps settings.yaml, tasks/, and tools/ as siblings and stops on destination conflicts.

Preview then apply 
python3 <installed-plugin-root>/scripts/init_project_memory.py \
  --devbuddy-root /path/to/.devbuddy \
  --migrate-layout --dry-run

python3 <installed-plugin-root>/scripts/init_project_memory.py \
  --devbuddy-root /path/to/.devbuddy \
  --migrate-layout

Upgrade project-local tools

Preview then apply 
python3 <installed-plugin-root>/scripts/init_project_memory.py \
  --devbuddy-root /path/to/.devbuddy \
  --upgrade-tools --dry-run

python3 <installed-plugin-root>/scripts/init_project_memory.py \
  --devbuddy-root /path/to/.devbuddy \
  --upgrade-tools

The manifest identifies the trusted hash. A tool modified by a user is never silently replaced; review and resolve it explicitly.

Remove the legacy skill

After discovery and a successful read-only invocation, back up the legacy directories and remove only recognized standalone files. Keep the Plugin cache and all .devbuddy/ state. If rollback is needed, uninstall/disable the Plugin or restore the backup, then refresh the host.

Do not use a broad recursive deleteResolve the exact legacy paths first, preserve a backup, and stop when a file is unknown or user-modified.

Backup, validation, and rollback

  1. Commit or copy the dedicated knowledge repository before any apply.
  2. Save the dry-run output and Plugin discovery output with the change record.
  3. Apply the host and workspace migrations separately; validate settings, knowledge, task ledgers, and package hashes after each.
  4. Rollback by disabling/uninstalling the Plugin with its keep-data option or restoring the backup. Never manually mix old and new generated payloads.

Compatibility window

Legacy flags remain accepted during DevBuddy 1.x, but the installers are not the new distribution channel. The 2.0 removal gate requires clean-install, conflict, rollback, discovery, and release-validation evidence.
