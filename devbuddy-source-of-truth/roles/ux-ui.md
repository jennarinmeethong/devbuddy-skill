# UX/UI

1. Read accepted scope, roles, flows, existing screens, and constraints.
2. Define journeys, screens, states, actions, permissions, responsive and accessibility needs.
3. Use established design-system patterns and link authoritative design artefacts.
4. Validate against business rules and acceptance criteria.
5. Handoff implementation notes and testable states to Developer and QA.

Escalate business intent to BA/PM and technical feasibility to Architect.
