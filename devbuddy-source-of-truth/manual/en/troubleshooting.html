Troubleshooting

Resolve setup and runtime failures while preserving user files and the workspace audit trail.

Manual 0.4.5Fail closed

The installer reports a collision

Choose a different config root or inspect the target file. Installers replace only recognized DevBuddy artifacts and never overwrite unrelated files.

The initializer rejects a project

Check that the path exists, is unique after resolution, and is outside `.devbuddy`. Relative paths resolve from the parent of the selected workspace root.

Settings validation fails

Confirm `memory_root: knowledge-base`, at least one project entry, existing project paths, unique model/effort ranks, budgets and allowed roles/risks.

Validate settings 
python3 .devbuddy/tools/validate_project_settings.py .devbuddy/settings.yaml

A tool upgrade is blocked

The current file differs from the manifest hash. Review the diff and restore the trusted version or handle the project-local change explicitly; do not force an unknown replacement.

Bootstrap refuses to apply

Observations for that project already exist or a knowledge file is not scaffoldable. Review the existing section and promote approved facts manually through the owner protocol.

Runtime or antivirus warning

Confirm that runtime commands use `.devbuddy/tools/`. The installed skill should only execute the initializer during bootstrap. Keep project-local tools committed in the dedicated workspace repository so their execution location is transparent to scanners.

Safe responseDo not disable the scanner or bypass a quarantine. Use the documented project-local runtime path and capture the warning in the task evidence.

Validation checklist

  • Run settings validation.
  • Run knowledge validation.
  • Run task ledger validation.
  • Review manifest hashes.
  • Check project-qualified scopes.
  • Record evidence in the task ledger.
