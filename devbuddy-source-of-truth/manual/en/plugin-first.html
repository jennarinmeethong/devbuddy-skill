Claude Code · Plugin-first

Install DevBuddy through the Plugin marketplace

New Claude Code installations use one marketplace Plugin. The Plugin bundles the portable core dependency and generated role/effort agents.

Add, install, and refresh

claude plugin validate plugin/devbuddy-claude-code; claude plugin marketplace add ./; claude plugin install devbuddy-claude-code@devbuddy --scope user --yes; claude plugin list --json; /reload-plugins; /devbuddy-claude-code:devbuddy <task>

The repository root contains .claude-plugin/marketplace.json. Claude Code namespaces Plugin skills, so the supported Plugin entrypoint is /devbuddy-claude-code:devbuddy; the unnamespaced /devbuddy form is retained only by the legacy standalone compatibility shim.

Update, verify, and roll back

claude plugin marketplace update devbuddy; claude plugin update devbuddy-claude-code@devbuddy; claude plugin list --json; claude plugin uninstall devbuddy-claude-code@devbuddy --keep-data

After update, run /reload-plugins and verify the namespaced entrypoint. To roll back, uninstall with --keep-data, restore the approved marketplace/plugin version, reinstall, and refresh. The legacy installer remains a dry-run-first compatibility path during DevBuddy 1.x.

Safety and ownership

  • Validate manifests before installation and use explicit --yes only after reviewing the source.
  • The Plugin depends on devbuddy-core; do not install a second standalone core skill.
  • Plugin files own host payloads; project state, secrets, task ledgers, and knowledge stay outside package artifacts.
  • Use the standalone installer only for an explicit migration report or approved legacy compatibility install.
