Use Profiles in detail

A Profile is a useful set of capabilities and roles for one type of work. Always inspect a preview first; only --apply saves it to a workspace.

Safe by defaultWorks across hostsReviewable changes

What a Profile is—and is not

A Profile tells DevBuddy which packages and roles fit work such as product delivery, cloud operations, or data/AI. It does not install a host plugin, grant write permission, enable production access, or create cost. Install one host plugin first by following the getting-started guide.

ThingPurpose
Host pluginConnects DevBuddy to Codex, Claude Code, or OpenCode.
ProfileSelects packages and roles for a workspace.
Role presetThe specialists DevBuddy should consider.
WorkspaceStores the selected profile in .devbuddy/packages.json.

Before starting: use the correct Terminal folder

Profile commands live in the DevBuddy repository, not in every project folder. Open Terminal at the repository root, where both profiles/ and scripts/profile_resolver.py exist. If your team does not have a checkout, ask an administrator for its approved path or commit; do not use a mutable branch for real work.

Verify your location 
pwd
ls profiles scripts/profile_resolver.py
python3 scripts/profile_resolver.py --list

If you see the profile catalogue, you are ready. Every command on this page is a preview unless it explicitly includes --apply.

Step 1: List profiles and choose the work type

List every profile 
python3 scripts/profile_resolver.py --list
ProfileUse it for
product-deliveryA feature, web site, or app: requirements, UX, architecture, frontend/backend, QA, and review.
cloud-operationsCI/CD, cloud, reliability, monitoring, or an incident.
data-aiData pipelines, analysis, model evaluation, and compliance.
support-knowledgeHelpdesk, FAQs, guides, and knowledge-base maintenance.
minimalThe smallest possible core setup.

Profiles beginning with data- are separate database capabilities and require least-privilege credentials and approval. Do not choose one just to read a CSV file or perform ordinary analysis.

Step 2: Preview a Profile before installing it

Replace <host> with codex, claude-code, or opencode. This only lists the packages and roles that would be used; it does not create or modify files.

Preview 
python3 scripts/profile_resolver.py product-delivery --platform <host>
# Codex example
python3 scripts/profile_resolver.py product-delivery --platform codex

Read the output: confirm the profile name, platform, packages, and roles. If a host or package is wrong, stop and choose another Profile. There is nothing to clean up yet because it was a preview.

To save the selection, replace <workspace> with the folder containing .devbuddy, then run the same preview with its path first:

Save the first Profile 
python3 scripts/profile_resolver.py product-delivery \
  --platform <host> --devbuddy-root <workspace>/.devbuddy

python3 scripts/profile_resolver.py product-delivery \
  --platform <host> --devbuddy-root <workspace>/.devbuddy --apply

Only the line with --apply writes packages.json. The write is atomic: invalid input never leaves a half-written file.

Step 3: Add a Profile without removing the current one

Use this when a workspace already handles product delivery and now needs data/AI, for example. The resolver keeps shared dependencies and preserves the currently active host.

Add data-ai 
python3 scripts/profile_resolver.py --add-profile data-ai \
  --platform <host> --devbuddy-root <workspace>/.devbuddy

python3 scripts/profile_resolver.py --add-profile data-ai \
  --platform <host> --devbuddy-root <workspace>/.devbuddy --apply

Inspect the added, retained, and removed sections before applying. If the command selects an unintended host, cancel it and pass the correct --platform; do not edit the JSON by hand.

Step 4: Remove a Profile you no longer need

Removal keeps every package or role still required by another Profile, so it is safer than deleting items in a file. This example removes data-ai and retains product-delivery.

Remove data-ai 
python3 scripts/profile_resolver.py --remove-profile data-ai \
  --platform <host> --devbuddy-root <workspace>/.devbuddy

python3 scripts/profile_resolver.py --remove-profile data-ai \
  --platform <host> --devbuddy-root <workspace>/.devbuddy --apply
A Profile is not a plugin uninstall. Removing a Profile changes only workspace composition. It does not remove the Codex, Claude Code, or OpenCode plugin, and it does not delete tasks, knowledge, or secrets below .devbuddy.

Step 5: Check state after adding or removing

Inspect saved composition 
python3 scripts/profile_resolver.py --status \
  --devbuddy-root <workspace>/.devbuddy

Confirm the profiles, active platform, and packages are what you intended. To undo a recent addition, remove that Profile, then add back the wanted one—always preview first.

Step 6: Understand how role presets are used

After saving a Profile, a normal request such as $devbuddy help plan this feature lets the Orchestrator propose the relevant roles. You do not need to invoke every role. For example, product-delivery can use a Requirements Analyst for acceptance criteria, an Architect for design, Frontend/Backend Engineers for implementation, QA for tests, and a Code Reviewer for independent review.

A Profile does not force every role into every task or bypass approval. DevBuddy must explain the reason, scope, risk, and approval point before dispatching impactful work.

Step 7: Use a preset with OpenCode

After selecting an OpenCode Profile, materialize only the needed preset into the project. The first command previews; the second writes agent files and never overwrites an existing definition.

OpenCode agent preset 
python3 <plugin-directory>/scripts/materialize_agents.py \
  --preset product-delivery --project-root <project>

python3 <plugin-directory>/scripts/materialize_agents.py \
  --preset product-delivery --project-root <project> --apply

cloud-operations, data-ai, and support-knowledge work in the same way. Files appear beneath <project>/.opencode/agents/devbuddy/. Read the OpenCode guide for host installation.

Common problems

Message or symptomWhat to do
Profile not foundRun --list from the repository root and copy the exact name.
Profile does not support hostCheck --platform; finish host plugin installation first.
Workspace not foundCreate one from the workspace step or correct its path.
Worried that a command will write filesRemove --apply; the resolver is then a dry run.
OpenCode says an agent file existsDo not overwrite it. Review it, use a different role, or let an administrator decide whether to move or remove it.

What to do after selecting a Profile

Ask DevBuddy to propose a plan and roles for a small task. Approve the scoped plan only when it is correct. Read Tasks and knowledge for durable evidence and Troubleshooting when a command stops with an error.
