Before you install

You need a current Codex CLI/Desktop session, permission to change its local Plugin configuration, and the marketplace source published by your team. A marketplace source is a local directory or Git repository that contains Plugins; its displayed name is assigned by Codex. The DevBuddy package ID is devbuddy-codex. Do not separately install devbuddy-core or the retired standalone skill.

Prepare, add, and inspect the marketplace

This repository is a ready-to-add Codex marketplace root. Its catalog is .agents/plugins/marketplace.json; the devbuddy entry resolves to ./plugins/devbuddy-codex. That path is maintained as a relative link to the generated Plugin payload, so keep both paths when cloning or packaging the repository. For another marketplace, use its root path or approved Git source instead of ..

Add this repository marketplace 
codex plugin marketplace list --json
codex plugin marketplace add . --json
codex plugin marketplace list --json
codex plugin list --available --json

For a new marketplace, create .agents/plugins/marketplace.json with a unique name, then add an entry whose source.path is ./plugins/devbuddy-codex. Ensure that path contains .codex-plugin/plugin.json, policy.installation, policy.authentication, and category. Copy the marketplace name returned by the list command; for this repository it is devbuddy.

Install, compose the profile, and refresh

Install using the exact package-and-marketplace selector. The JSON output must show the Plugin as installed and enabled. Then resolve the Codex profile: use dry-run first, and apply only to the intended workspace.

Plugin and profile 
codex plugin add devbuddy-codex@devbuddy --json
codex plugin list --json
python3 scripts/profile_resolver.py profiles/codex.yaml --platform codex --dry-run
python3 scripts/profile_resolver.py profiles/codex.yaml --platform codex --apply --devbuddy-root <workspace>/.devbuddy

Start a new Codex thread after an install, update, enable, or removal so the host loads the current Plugin payload.

Invoke DevBuddy

Explicit entrypoint 
$devbuddy <task>
$devbuddy reviewer <task>
$devbuddy owner loop <task>

The adapter routes the request to the Orchestrator. Profile composition is selected before workspace writes; switching hosts does not mutate the shared settings file.

Model and effort transport

  • Every specialist dispatch carries an approved model and reasoning_effort selected from workspace settings.
  • The adapter blocks when the subagent capability cannot accept either value; it never silently substitutes the owner or an unapproved model.
  • Use one bounded role slice, project-qualified write scope, and a structured JSON slice record for hand-off.
  • Specialists cannot write .devbuddy/ directly; the owner validates evidence and commits canonical knowledge.

Workspace runtime

After initialization, operational Python runs from the five direct files under .devbuddy/tools/. Verify the exact path and hash in tools/manifest.json before invoking a runtime command.

Health checks 
python3 .devbuddy/tools/validate_project_settings.py .devbuddy/settings.yaml
python3 .devbuddy/tools/validate_knowledge.py --devbuddy-root .devbuddy
python3 .devbuddy/tools/task_memory.py validate --devbuddy-root .devbuddy --task-id <task-id>

Database access remains Plugin-owned Tier 2 capability and blocks as waiting_user when the selected package, manifest, read-only principal, or target approval is missing.

Update, remove, and migration

For this local repository marketplace, update the approved source and its Plugin cachebuster, then add the package again. A Git marketplace source uses an upgrade first. Verify the result and open a new thread.

Lifecycle 
# local repository: after updating the Plugin cachebuster
codex plugin add devbuddy-codex@devbuddy --json
codex plugin list --json
# Git marketplace only: refresh its named source, then add its package
codex plugin marketplace upgrade <marketplace>
# uninstall the package; this removes local Plugin config/cache
codex plugin remove devbuddy-codex@devbuddy

Remove the marketplace source only when no installed Plugin needs it: codex plugin marketplace remove devbuddy. Neither command should remove workspace state under .devbuddy/. The legacy installer is retained only for the 1.x compatibility window: python3 devbuddy-codex/scripts/install_codex_adapter.py --migration-report. It is a read-only migration check, not a Plugin installer.
