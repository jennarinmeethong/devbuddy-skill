Codex Skill adapter

Status: implemented against common specification 0.1.1. Validate this adapter in the target Codex environment before use.

Target format

The adapter uses the current Codex Skill structure: SKILL.md, agents/openai.yaml, role profiles, settings/schema, templates, standard-library validation scripts, scenarios, and a local bilingual manual.

Install and configure

  1. Copy the completed devbuddy-codex folder to the user-approved Codex skills location.
  2. Verify Codex discovers SKILL.md and agents/openai.yaml.
  3. Create <project-root>/.devbuddy/settings.yaml with approved ranked model/effort allowlists, concurrency, timeout, and retry values.
  4. Run the documented read-only validation commands.
  5. Invoke $devbuddy owner <task>.

Codex dispatch behaviour

The Orchestrator selects the least-capable approved model and lowest approved effort sufficient for every specialist slice, records the reason, and passes both explicitly to the Codex subagent call. Missing settings, approval, resource budget, or subagent capability blocks the task as waiting_user; the Orchestrator does not replace the specialist.

Troubleshooting

  • If Codex cannot create a subagent with model and reasoning_effort parameters, do not run a substitute workflow; ask the user to enable the capability or choose another approved platform.
  • If project settings are absent or invalid, validate them before dispatch.
  • Do not bypass Git, cost, tool, approval, privacy, or endpoint policy to make the adapter appear usable.
