Codex Skill adapter

Status: not implemented at version 0.1.0. The source-of-truth defines the target, but the Codex adapter has not yet passed its checklist.

Target format

The completed adapter must use the current Codex Skill structure: a folder with SKILL.md and agents/openai.yaml. It may include references, templates, scripts, and assets required by the platform adaptation.

Installation when the checklist is complete

  1. Confirm every required item in devbuddy-codex/adapter-implementation-checklist.md is done.
  2. Read the completed adapter SKILL.md and verify its current Codex compatibility.
  3. Copy the adapter folder to the user-approved Codex skills location, normally $CODEX_HOME/skills or ~/.codex/skills when that home is used by the active Codex installation.
  4. Restart or refresh the Codex environment if required by that installation, then invoke the Skill with its documented prompt.
  5. Run read-only validation and verify settings, memory location, tool availability, and adapter/manual conformance.

Do not install a plugin, runtime, or dependency merely to complete these steps. Ask the user first.

Configuration

Project overrides belong in <project-root>/.devbuddy/settings.yaml. The file may point at an external memory root such as an Obsidian vault, but it must contain no knowledge content, secrets, or personal data. Explicit user instructions override approved project settings; common settings provide the remaining defaults.

Troubleshooting

  • If Codex cannot discover the adapter, verify the target location, SKILL.md frontmatter, and agents/openai.yaml.
  • If a platform capability cannot support a common policy, keep the related checklist item incomplete and document the limitation.
  • Do not bypass Git, cost, tool, approval, privacy, or endpoint policy to make the adapter appear complete.
