Codex adapter

Let the Orchestrator route the work.

The normal entrypoint is $devbuddy <task>. Codex selects the role graph, model, and reasoning effort before dispatch.

Install and configure

  1. Install the Codex skill with its dry-run-first installer.
  2. Create <project-root>/.devbuddy/settings.yaml with user-approved model/effort allowlists and budgets.
  3. Run the read-only validators, then invoke $devbuddy <task>.

Invocation contract

$devbuddy <task>
$devbuddy loop <task>

The Orchestrator owns intake, risk, dependencies, approvals, locks, model/effort selection, and handoffs. Explicit role and owner forms are advanced routing overrides, not prerequisites.

Codex dispatch

Every specialist call receives explicit model and reasoning_effort values from the project allowlists. If the capability or handoff cannot verify either value, the task becomes waiting_user; the Orchestrator never substitutes itself for a specialist.

Memory and validation

KnowledgeBase.md, core memory, typed knowledge, and task ledgers stay under <project-root>/.devbuddy/. Prepare a reviewable repository inventory with python3 scripts/bootstrap_knowledge.py --project-root <project-root> --dry-run; use --apply only after review. It writes only Context.md and KnowledgeBase.md, never overwrites non-empty existing files, and never invents typed canonical entities. Validate with python3 scripts/validate_knowledge.py --project-root <project-root>, or use --root <approved-external-memory-root> for an external root.
