Claude Code adapter

Let the Orchestrator route the work.

The normal entrypoint is /devbuddy <task>. Claude selects the specialist role graph, model, and effort before dispatch.

Install and configure

  1. Install with the dry-run-first install_claude_adapter.py workflow.
  2. Create <project-root>/.devbuddy/settings.yaml with approved model/effort allowlists and budgets.
  3. Verify the 27 devbuddy-<role>-<effort> definitions are available.
  4. Run the validation commands, then invoke /devbuddy <task>.

Invocation contract

/devbuddy <task>
/devbuddy loop <task>

The Orchestrator owns intake, risk, dependencies, approvals, locks, model/effort selection, and handoffs. Explicit /devbuddy <role> <task> and /devbuddy owner <task> forms are advanced routing overrides, not prerequisites.

Claude dispatch

Effort is carried by the selected agent definition's effort frontmatter. The approved model is passed per Agent call. Agent definitions must not pin a model. If a required agent, approval, budget, or selection cannot be verified, the task becomes waiting_user; the Orchestrator never substitutes itself for a specialist.

Memory and validation

KnowledgeBase.md, core memory, typed knowledge, and task ledgers stay under <project-root>/.devbuddy/. Validate the default root with python3 scripts/validate_knowledge.py --project-root <project-root>, or an external root with --root <approved-external-memory-root>.
