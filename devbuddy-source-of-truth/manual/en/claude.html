Claude Code adapter

Install devbuddy-claude-code@devbuddy, refresh the session, and invoke the namespaced DevBuddy command explicitly.

Manual 0.4.6Plugin 1.0.1Explicit invocation

Before you install

Use a current, authenticated Claude Code installation, permission to change the chosen Plugin scope, and a readable marketplace source. This repository publishes its catalog at .claude-plugin/marketplace.json. Choose one scope and use it consistently: user is shared by your local projects, project is for the current repository, and local is machine-local configuration.

Add and inspect the marketplace

From the repository root, validate the package. Then add the marketplace using the same scope you will use for the Plugin. Replace . with an approved repository path, Git URL, or GitHub source when installing from elsewhere.

Marketplace discovery 
claude plugin validate plugin/devbuddy-claude-code
claude plugin marketplace add . --scope user
claude plugin marketplace list

The catalog name is devbuddy; the full selector is devbuddy-claude-code@devbuddy. If the source was already added, inspect the list rather than adding a duplicate.

Install, verify, and refresh

Install the exact selector with the matching scope. Review the marketplace-declared command before using --yes; it accepts that command without an interactive prompt. Verify discovery, then reload Plugins inside Claude Code.

Marketplace install 
claude plugin install devbuddy-claude-code@devbuddy --scope user --yes
claude plugin list --json
# in Claude Code
/reload-plugins

The Plugin bundles the Claude host adapter, generated role/effort agents, references, schemas, templates, and the devbuddy-core dependency. Do not install a separate global devbuddy skill.

Invoke DevBuddy

Namespaced entrypoint 
/devbuddy-claude-code:devbuddy <task>
/devbuddy-claude-code:devbuddy reviewer <task>
/devbuddy-claude-code:devbuddy owner loop <task>

Claude Code namespaces Plugin skills. The bare /devbuddy form is legacy standalone compatibility only and must not be documented as the Plugin entrypoint.

Dispatch contract

  • disable-model-invocation: true keeps the workflow behind an explicit user invocation.
  • Each specialist receives one approved model through Claude's Agent tool and one generated devbuddy-<role>-<effort> agent.
  • Effort is carried by the generated agent metadata; model approval is carried per dispatch, not pinned in the agent file.
  • Missing model, effort, rtk_required, tool, or approval prerequisites fail closed as blocked or waiting_user.
  • Specialists write only the reserved source scope and return structured JSON slice records; the owner controls canonical .devbuddy/ writes.

Workspace runtime

Use the initializer and five direct project-local tools under .devbuddy/tools/. Confirm the exact path and matching hash in tools/manifest.json; do not run source-maintenance scripts from the Plugin as delivery tools.

Health checks 
python3 .devbuddy/tools/validate_project_settings.py .devbuddy/settings.yaml
python3 .devbuddy/tools/validate_knowledge.py --devbuddy-root .devbuddy
python3 .devbuddy/tools/task_memory.py validate --devbuddy-root .devbuddy --task-id <task-id>

Database work is a Plugin-owned Tier 2 capability. It requires the selected engine adapter, manifest, read-only principal, database ID, and target-specific approval; a missing package blocks instead of falling back to a driver or shell.

Update, disable, remove, and migration

Lifecycle 
claude plugin marketplace update devbuddy
claude plugin update devbuddy-claude-code@devbuddy
claude plugin list --json
# in Claude Code
/reload-plugins
# remove from the same scope used to install; preserve persistent Plugin data
claude plugin uninstall devbuddy-claude-code@devbuddy --scope user --keep-data

Use claude plugin disable devbuddy-claude-code@devbuddy when you need a reversible pause, and claude plugin enable devbuddy-claude-code@devbuddy to restore it. Remove the devbuddy marketplace only after no installed Plugin needs it. During DevBuddy 1.x the old installer is a read-only migration shim: python3 devbuddy-claude/scripts/install_claude_adapter.py --migration-report. It never removes workspace state.
