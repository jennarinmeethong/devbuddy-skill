Claude Code Skill adapter

Status: implemented against common specification 0.1.0. Every required item in devbuddy-claude/adapter-implementation-checklist.md is done. Validate this adapter in the target Claude Code environment before use.

Target format

The adapter uses the Claude Code Skill structure: SKILL.md invoked explicitly as /devbuddy, role profiles, 27 installable subagent definitions, settings/schema, templates, standard-library validation scripts, scenarios, and a local bilingual manual.

Prerequisites

  • Claude Code installed, authenticated, and supported in the target environment.
  • Subagent support including the effort frontmatter field, which carries the per-dispatch effort level.
  • Python 3 for the bundled standard-library validation scripts. No packages are installed.
  • Explicit user approval for any installation, update, paid account, or model usage.

Verify the actual installation with claude doctor only after the user authorises running it. Official setup guidance: Claude Code documentation.

Install and configure

  1. Confirm every required item in devbuddy-claude/adapter-implementation-checklist.md is done.
  2. Preview the file list with python3 scripts/install_claude_adapter.py; dry run is the default.
  3. Install with python3 scripts/install_claude_adapter.py --apply. The skill goes to ~/.claude/skills/devbuddy/ and the 27 devbuddy-<role>-<effort> subagents to ~/.claude/agents/.
  4. Create <project-root>/.devbuddy/settings.yaml with approved ranked model/effort allowlists, concurrency, timeout, and retry values.
  5. Restart the session, run the documented read-only validation commands, then invoke /devbuddy owner <task>.

Never copy credentials, connection strings, or personal data into Claude settings or prompts.

Claude dispatch behaviour

The Orchestrator selects the least-capable approved model and lowest approved effort sufficient for every specialist slice and records the reason. Claude Code fixes effort per agent definition and allows the model to be overridden per call, so the adapter installs one subagent per role and effort tier and passes the model explicitly on each Agent call. Agent definitions must not pin a model. Missing settings, approval, resource budget, or an uninstalled subagent blocks the task as waiting_user; the Orchestrator does not replace the specialist.

Adapter behaviour

The Claude adapter preserves common policy: Thai user communication, English internal handoffs, no guessing, Git read-only default, user approval for cost/tool/install/external actions, knowledge impact approval, and adapter checklist evidence. It enforces policy through skill instructions only: it does not modify .claude/settings.json and installs no hooks, so Claude Code's own permission prompts remain the user's backstop.

Troubleshooting

  • If a required devbuddy-<role>-<effort> subagent is missing, re-run the installer; do not substitute the Orchestrator for the specialist.
  • If the effort level actually used cannot be confirmed, treat the dispatch as blocked rather than completed.
  • If project settings are absent or invalid, validate them before dispatch.
  • If permissions, tool access, or model availability differ from common policy, mark the checklist item incomplete and record a remark.
  • Do not use a permission-bypass mode to work around DevBuddy approvals.
