Claude Code adapter

ติดตั้ง devbuddy-claude-code@devbuddy, refresh session แล้วเรียก DevBuddy ด้วยคำสั่งที่มี namespace อย่างชัดเจน

Manual 0.4.6Plugin 1.0.1Explicit invocation

ก่อนติดตั้ง

ใช้ Claude Code รุ่นปัจจุบันที่ login แล้ว, มีสิทธิ์แก้ Plugin scope ที่เลือก และเข้าถึง marketplace source ได้ Catalog ของ repository นี้อยู่ที่ .claude-plugin/marketplace.json เลือก scope เดียวและใช้ให้สม่ำเสมอ: user ใช้ร่วมทุก project ในเครื่อง, project สำหรับ repository ปัจจุบัน และ local สำหรับ configuration ในเครื่อง

เพิ่มและตรวจ marketplace

จาก repository root ให้ validate package ก่อน แล้วเพิ่ม marketplace ด้วย scope เดียวกับที่จะใช้ติดตั้ง Plugin แทน . ด้วย repository path, Git URL หรือ GitHub source ที่อนุมัติ เมื่อติดตั้งจาก source อื่น

Marketplace discovery 
claude plugin validate plugin/devbuddy-claude-code
claude plugin marketplace add . --scope user
claude plugin marketplace list

ชื่อ catalog คือ devbuddy และ selector เต็มคือ devbuddy-claude-code@devbuddy หากเพิ่ม source ไปแล้วให้ตรวจจาก list แทนการเพิ่มซ้ำ

ติดตั้ง, ตรวจสอบ และ refresh

ติดตั้งด้วย selector และ scope เดียวกัน ตรวจ marketplace-declared command ก่อนใช้ --yes เพราะ flag นี้ยอมรับคำสั่งนั้นโดยไม่ถามใน interactive prompt หลังติดตั้งให้ตรวจ discovery แล้ว reload Plugin ภายใน Claude Code

Marketplace install 
claude plugin install devbuddy-claude-code@devbuddy --scope user --yes
claude plugin list --json
# ใน Claude Code
/reload-plugins

Plugin bundle Claude host adapter, generated role/effort agents, references, schemas, templates และ dependency devbuddy-core มาให้แล้ว ไม่ต้องติดตั้ง global devbuddy skill แยก

เรียกใช้ DevBuddy

Namespaced entrypoint 
/devbuddy-claude-code:devbuddy <task>
/devbuddy-claude-code:devbuddy reviewer <task>
/devbuddy-claude-code:devbuddy owner loop <task>

Claude Code จะ namespace skill ของ Plugin ดังนั้น /devbuddy แบบ bare ใช้เฉพาะ legacy standalone compatibility และไม่ใช่ entrypoint ของ Plugin

Dispatch contract

  • disable-model-invocation: true ทำให้ workflow เปิดได้จาก explicit user invocation เท่านั้น
  • specialist แต่ละคนได้รับ model ที่อนุมัติผ่าน Claude Agent tool และ generated agent แบบ devbuddy-<role>-<effort> หนึ่งตัว
  • effort อยู่ใน metadata ของ generated agent ส่วน model ต้องส่งและตรวจ approval ในแต่ละ dispatch ไม่ pin ไว้ใน agent file
  • ถ้าขาด model, effort, rtk_required, tool หรือ approval จะ fail closed เป็น blocked หรือ waiting_user
  • specialist เขียนได้เฉพาะ source scope ที่ reserve และคืน structured JSON slice record; owner เท่านั้นที่เขียน canonical .devbuddy/

Workspace runtime

ใช้ initializer และ project-local tools 5 ตัวใต้ .devbuddy/tools/ ตรวจ path และ hash ให้ตรงกับ tools/manifest.json และอย่านำ source-maintenance script จาก Plugin ไปใช้เป็น delivery tool

Health checks 
python3 .devbuddy/tools/validate_project_settings.py .devbuddy/settings.yaml
python3 .devbuddy/tools/validate_knowledge.py --devbuddy-root .devbuddy
python3 .devbuddy/tools/task_memory.py validate --devbuddy-root .devbuddy --task-id <task-id>

Database เป็น Tier 2 ที่ Plugin เป็นเจ้าของ ต้องมี engine adapter, manifest, read-only principal, database ID และ target-specific approval ถ้า package หายให้ block แทนการ fallback ไป driver หรือ shell

Update, disable, remove และ migration

Lifecycle 
claude plugin marketplace update devbuddy
claude plugin update devbuddy-claude-code@devbuddy
claude plugin list --json
# ใน Claude Code
/reload-plugins
# ถอนจาก scope เดียวกับที่ติดตั้ง และเก็บ persistent Plugin data
claude plugin uninstall devbuddy-claude-code@devbuddy --scope user --keep-data

ใช้ claude plugin disable devbuddy-claude-code@devbuddy เมื่อต้องการพักการใช้งานแบบย้อนกลับได้ และใช้ claude plugin enable devbuddy-claude-code@devbuddy เพื่อเปิดกลับ ลบ marketplace devbuddy ได้ต่อเมื่อไม่มี Plugin ที่ติดตั้งใช้ source นี้แล้ว ระหว่าง DevBuddy 1.x installer เดิมเป็น migration shim แบบอ่านอย่างเดียว: python3 devbuddy-claude/scripts/install_claude_adapter.py --migration-report และไม่ลบ workspace state
