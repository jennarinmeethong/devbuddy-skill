Claude Code Skill adapter

สถานะ: implement เสร็จแล้วตามข้อกำหนดกลางเวอร์ชัน 0.1.0 ทุกรายการที่จำเป็นใน devbuddy-claude/adapter-implementation-checklist.md เป็น done ควรตรวจสอบ adapter ในเครื่องเป้าหมายก่อนใช้งานจริง

รูปแบบเป้าหมาย

adapter ใช้โครงสร้าง Claude Code Skill ได้แก่ SKILL.md ที่เรียกอย่างชัดเจนด้วย /devbuddy, ไฟล์บทบาท, ไฟล์นิยาม subagent 27 ไฟล์สำหรับติดตั้ง, settings และ schema, templates, สคริปต์ตรวจสอบที่ใช้เฉพาะไลบรารีมาตรฐาน, ชุด scenario และคู่มือสองภาษาในตัว

สิ่งที่ต้องมีก่อน

  • มี Claude Code ที่ติดตั้งและเข้าสู่ระบบแล้วในเครื่องเป้าหมาย
  • รองรับ subagent รวมถึงฟิลด์ effort ใน frontmatter ซึ่งเป็นตัวระบุระดับ effort ของแต่ละการส่งงาน
  • มี Python 3 สำหรับรันสคริปต์ตรวจสอบที่แถมมา ไม่มีการติดตั้งแพ็กเกจใด ๆ
  • การติดตั้ง การอัปเดต บัญชีแบบเสียเงิน หรือการใช้ model ต้องได้รับอนุมัติจากผู้ใช้ก่อน

ตรวจสถานะจริงด้วย claude doctor ได้หลังผู้ใช้อนุมัติเท่านั้น ดูคู่มือทางการ: เอกสาร Claude Code

วิธีติดตั้งและตั้งค่า

  1. ตรวจว่าทุกรายการที่ต้องทำใน devbuddy-claude/adapter-implementation-checklist.md เป็น done
  2. ดูรายการไฟล์ก่อนด้วย python3 scripts/install_claude_adapter.py ซึ่งเป็นโหมดทดลองโดยค่าเริ่มต้น
  3. ติดตั้งจริงด้วย python3 scripts/install_claude_adapter.py --apply ตัว skill จะไปที่ ~/.claude/skills/devbuddy/ และ subagent devbuddy-<role>-<effort> ทั้ง 27 ตัวไปที่ ~/.claude/agents/
  4. สร้าง <project-root>/.devbuddy/settings.yaml พร้อมรายการ model/effort ที่อนุมัติและจัดลำดับแล้ว รวมถึงค่า concurrency, timeout และ retry
  5. เริ่มเซสชันใหม่ รันคำสั่งตรวจสอบแบบอ่านอย่างเดียวตามคู่มือ แล้วจึงเรียก /devbuddy owner <task>

ห้าม copy credential, connection string หรือข้อมูลส่วนบุคคลลง Claude settings หรือ prompt

พฤติกรรมการส่งงานบน Claude

Orchestrator จะเลือก model ที่อนุมัติแล้วซึ่งมีความสามารถต่ำที่สุด และระดับ effort ต่ำที่สุดเท่าที่เพียงพอกับงานแต่ละส่วน พร้อมบันทึกเหตุผล เนื่องจาก Claude Code กำหนด effort ที่ไฟล์นิยาม agent และให้ override model ได้รายครั้ง adapter จึงติดตั้ง subagent หนึ่งตัวต่อหนึ่งบทบาทและหนึ่งระดับ effort แล้วส่ง model อย่างชัดเจนในทุกครั้งที่เรียก Agent ไฟล์นิยาม agent ต้องไม่กำหนด model ตายตัว หากขาดการตั้งค่า การอนุมัติ งบทรัพยากร หรือยังไม่ได้ติดตั้ง subagent ที่ต้องใช้ งานจะถูกบล็อกเป็น waiting_user และ Orchestrator จะไม่ทำงานแทนผู้เชี่ยวชาญ

พฤติกรรมของ adapter

Claude adapter รักษานโยบายกลางไว้ครบ ได้แก่ สื่อสารกับผู้ใช้เป็นภาษาไทย ส่งต่องานภายในเป็นภาษาอังกฤษ ห้ามเดา Git อ่านอย่างเดียวโดยปริยาย ต้องขออนุมัติก่อนมีค่าใช้จ่าย ติดตั้งเครื่องมือ หรือทำงานกับระบบภายนอก ต้องมี Knowledge Impact Approval และต้องมีหลักฐานใน checklist โดยบังคับใช้ผ่านคำสั่งใน skill เท่านั้น ไม่แก้ไข .claude/settings.json และไม่ติดตั้ง hook การถามสิทธิ์ตามปกติของ Claude Code จึงยังเป็นด่านป้องกันสุดท้ายของผู้ใช้

แก้ปัญหา

  • หากไม่พบ subagent devbuddy-<role>-<effort> ที่ต้องใช้ ให้รันตัวติดตั้งใหม่ ห้ามให้ Orchestrator ทำงานแทนผู้เชี่ยวชาญ
  • หากยืนยันระดับ effort ที่ใช้จริงไม่ได้ ให้ถือว่าการส่งงานนั้นถูกบล็อก ไม่ใช่สำเร็จ
  • หากไม่มีไฟล์ตั้งค่าโครงการหรือไฟล์ไม่ถูกต้อง ให้ตรวจสอบให้ผ่านก่อนส่งงาน
  • หากสิทธิ์ การเข้าถึงเครื่องมือ หรือ model ที่ใช้ได้ต่างจากนโยบายกลาง ให้มาร์ครายการใน checklist ว่ายังไม่เสร็จและใส่หมายเหตุ
  • ห้ามใช้โหมดข้ามการขอสิทธิ์เพื่อเลี่ยงการอนุมัติของ DevBuddy
