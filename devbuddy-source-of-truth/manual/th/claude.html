Claude Code adapter

ให้ Orchestrator เป็นผู้เลือกเส้นทางงาน

รูปแบบปกติคือ /devbuddy <task> Claude จะประเมินงาน เลือกกราฟ role, model และ effort ก่อน dispatch

ติดตั้งและตั้งค่า

  1. ติดตั้งผ่าน workflow ของ install_claude_adapter.py ที่มี dry run เป็นค่าเริ่มต้น
  2. สร้าง <project-root>/.devbuddy/settings.yaml พร้อม model/effort allowlist และ budget
  3. ตรวจว่ามี definition devbuddy-<role>-<effort> ครบ 27 ไฟล์
  4. รัน validation แล้วเรียก /devbuddy <task>

Invocation contract

/devbuddy <task>
/devbuddy loop <task>

Orchestrator รับผิดชอบ intake, risk, dependency, approval, lock, การเลือก model/effort และ handoff การระบุ /devbuddy <role> <task> หรือ /devbuddy owner <task> เป็นตัวเลือกขั้นสูง ไม่ใช่สิ่งที่ต้องใช้เป็นปกติ

การ dispatch บน Claude

ระดับ effort มาจาก frontmatter effort ของ agent ที่เลือก ส่วน model ส่งไปกับ Agent call แต่ละครั้ง ห้าม pin model ใน agent definition หาก agent, approval, budget หรือ selection ตรวจสอบไม่ได้ งานจะเป็น waiting_user และ Orchestrator จะไม่ทำงานแทน specialist

Memory และ validation

KnowledgeBase.md, core memory, typed knowledge และ task ledger อยู่ใต้ <project-root>/.devbuddy/ เตรียม inventory ของ repository ที่ตรวจทานได้ด้วย python3 scripts/bootstrap_knowledge.py --project-root <project-root> --dry-run และใช้ --apply หลังตรวจทานแล้วเท่านั้น สคริปต์เขียนเฉพาะ Context.md กับ KnowledgeBase.md ไม่เขียนทับไฟล์เดิมที่มีเนื้อหา และไม่สร้าง typed canonical entity เอง ใช้ python3 scripts/validate_knowledge.py --project-root <project-root> หรือใช้ --root <approved-external-memory-root> เมื่อเป็น external root
