ก่อนติดตั้ง

ต้องมี Codex CLI/Desktop รุ่นปัจจุบัน, สิทธิ์แก้ Plugin configuration ในเครื่อง และ marketplace source ที่ทีมเผยแพร่ไว้ marketplace source คือ directory ในเครื่องหรือ Git repository ที่รวม Plugin และ Codex จะกำหนดชื่อ marketplace ให้เอง Package ID ของ DevBuddy คือ devbuddy-codex ไม่ต้องติดตั้ง devbuddy-core หรือ standalone skill เดิมแยกต่างหาก

เตรียม, เพิ่ม และตรวจ marketplace

repository นี้เป็น Codex marketplace root ที่พร้อมเพิ่มได้ Catalog อยู่ที่ .agents/plugins/marketplace.json และ entry devbuddy ชี้ไปที่ ./plugins/devbuddy-codex path นี้ถูกดูแลเป็น relative link ไปยัง generated Plugin payload จึงต้องเก็บทั้งสอง path เมื่อ clone หรือ package repository หากใช้ marketplace อื่นให้แทน . ด้วย root path หรือ Git source ที่อนุมัติ

เพิ่ม marketplace ของ repository นี้ 
codex plugin marketplace list --json
codex plugin marketplace add . --json
codex plugin marketplace list --json
codex plugin list --available --json

หากจะสร้าง marketplace ใหม่ ให้สร้าง .agents/plugins/marketplace.json ที่มี name ไม่ซ้ำ แล้วเพิ่ม entry ซึ่งมี source.path เป็น ./plugins/devbuddy-codex ตรวจว่า path นั้นมี .codex-plugin/plugin.json, policy.installation, policy.authentication และ category คัดลอก marketplace name จากผลลัพธ์ list; สำหรับ repository นี้คือ devbuddy

ติดตั้ง, compose profile และ refresh

ติดตั้งด้วย selector ที่ระบุ package และ marketplace ให้ตรงกัน JSON ต้องแสดงว่า Plugin เป็น installed และ enabled จากนั้น resolve profile สำหรับ Codex: เริ่มด้วย dry-run แล้ว apply เฉพาะ workspace ที่ตั้งใจ

Plugin และ profile 
codex plugin add devbuddy-codex@devbuddy --json
codex plugin list --json
python3 scripts/profile_resolver.py profiles/codex.yaml --platform codex --dry-run
python3 scripts/profile_resolver.py profiles/codex.yaml --platform codex --apply --devbuddy-root <workspace>/.devbuddy

หลัง install, update, enable หรือ remove ให้เปิด Codex thread ใหม่ เพื่อให้ host โหลด Plugin payload ปัจจุบัน

เรียกใช้ DevBuddy

Entrypoint แบบ explicit 
$devbuddy <task>
$devbuddy reviewer <task>
$devbuddy owner loop <task>

adapter จะส่งคำขอให้ Orchestrator และต้องเลือก profile ก่อนเขียน workspace composition; การสลับ host ไม่เปลี่ยน settings ร่วม

การส่ง model และ effort

  • ทุก specialist dispatch ต้องมี model และ reasoning_effort ที่อนุมัติแล้วจาก workspace settings
  • adapter จะ block ถ้า subagent capability รับค่าใดค่าหนึ่งไม่ได้ และไม่แทนด้วย owner หรือ model ที่ไม่ได้อนุมัติ
  • ใช้ role slice ที่มีขอบเขต, project-qualified write scope และ structured JSON slice record สำหรับ hand-off
  • specialist ห้ามเขียน .devbuddy/ โดยตรง; owner ต้องตรวจ evidence และ commit canonical knowledge

Workspace runtime

หลัง initialize แล้ว Python operational จะรันจากไฟล์ตรง 5 ตัวใต้ .devbuddy/tools/ ให้ตรวจ path และ hash ใน tools/manifest.json ก่อนเรียก runtime command

Health checks 
python3 .devbuddy/tools/validate_project_settings.py .devbuddy/settings.yaml
python3 .devbuddy/tools/validate_knowledge.py --devbuddy-root .devbuddy
python3 .devbuddy/tools/task_memory.py validate --devbuddy-root .devbuddy --task-id <task-id>

Database ยังเป็น Plugin-owned Tier 2 และจะหยุดเป็น waiting_user ถ้า package, manifest, read-only principal หรือ target approval ไม่ครบ

Update, remove และ migration

สำหรับ marketplace ใน repository นี้ซึ่งเป็น local ให้ update source ที่อนุมัติและ Plugin cachebuster แล้ว add package ใหม่ ส่วน Git marketplace ให้ upgrade ก่อน ตรวจผลลัพธ์และเปิด thread ใหม่

Lifecycle 
# local repository: หลัง update Plugin cachebuster
codex plugin add devbuddy-codex@devbuddy --json
codex plugin list --json
# Git marketplace เท่านั้น: refresh source ที่ตั้งชื่อไว้ก่อน add package
codex plugin marketplace upgrade <marketplace>
# ถอน package: ลบ local Plugin config/cache
codex plugin remove devbuddy-codex@devbuddy

ให้ลบ marketplace source ด้วย codex plugin marketplace remove devbuddy เฉพาะเมื่อไม่มี Plugin ที่ติดตั้งตัวใดต้องใช้ source นั้น คำสั่งเหล่านี้ต้องไม่ลบ workspace state ใต้ .devbuddy/ Installer เดิมเหลือไว้เฉพาะ compatibility window 1.x: python3 devbuddy-codex/scripts/install_codex_adapter.py --migration-report ซึ่งเป็น migration check แบบอ่านอย่างเดียว ไม่ใช่ตัวติดตั้ง Plugin
