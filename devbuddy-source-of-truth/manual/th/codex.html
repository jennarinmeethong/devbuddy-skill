Codex adapter

ให้ Orchestrator เป็นผู้เลือกเส้นทางงาน

รูปแบบปกติคือ $devbuddy <task> Codex จะเลือกกราฟ role, model และ reasoning effort ก่อน dispatch

ติดตั้งและตั้งค่า

  1. ติดตั้ง Codex skill ด้วย installer ที่มี dry run เป็นค่าเริ่มต้น
  2. สร้าง <project-root>/.devbuddy/settings.yaml พร้อม model/effort allowlist และ budget ที่ user อนุมัติ
  3. รัน validator แบบ read-only แล้วเรียก $devbuddy <task>

Invocation contract

$devbuddy <task>
$devbuddy loop <task>

Orchestrator รับผิดชอบ intake, risk, dependency, approval, lock, การเลือก model/effort และ handoff การระบุ role หรือ owner เองเป็นตัวเลือกขั้นสูง ไม่ใช่สิ่งที่ต้องใช้เป็นปกติ

การ dispatch บน Codex

ทุก specialist call ต้องได้รับค่า model และ reasoning_effort อย่างชัดเจนจาก project allowlist หาก capability หรือ handoff ยืนยันค่าใดไม่ได้ งานจะเป็น waiting_user และ Orchestrator จะไม่ทำงานแทน specialist

Memory และ validation

KnowledgeBase.md, core memory, typed knowledge และ task ledger อยู่ใต้ <project-root>/.devbuddy/ เตรียม inventory ของ repository ที่ตรวจทานได้ด้วย python3 scripts/bootstrap_knowledge.py --project-root <project-root> --dry-run และใช้ --apply หลังตรวจทานแล้วเท่านั้น สคริปต์เขียนเฉพาะ Context.md กับ KnowledgeBase.md ไม่เขียนทับไฟล์เดิมที่มีเนื้อหา และไม่สร้าง typed canonical entity เอง ใช้ python3 scripts/validate_knowledge.py --project-root <project-root> หรือใช้ --root <approved-external-memory-root> เมื่อเป็น external root
