ใช้ Profile อย่างละเอียด

Profile คือชุดความสามารถและบทบาทที่เหมาะกับงานหนึ่งประเภท คุณเริ่มจากดูผลจำลองเสมอ แล้วจึงสั่งบันทึกลง workspace ด้วย --apply

ปลอดภัยโดย defaultใช้ได้กับทุก hostย้อนรายการได้

Profile คืออะไร และไม่ใช่อะไร

Profile ช่วยบอก DevBuddy ว่างานนี้ควรมี package และ role ใดบ้าง เช่น งานสร้าง product, cloud หรือ data/AI มัน ไม่ ติดตั้ง plugin ของ host ให้เอง, ไม่ให้สิทธิ์เขียนไฟล์, ไม่เปิด production และไม่ทำให้เกิดค่าใช้จ่าย คุณยังต้องติดตั้ง host plugin หนึ่งตัวก่อนตาม คู่มือเริ่มต้น

สิ่งนี้ทำหน้าที่
Host pluginเชื่อม DevBuddy กับ Codex, Claude Code หรือ OpenCode
Profileเลือกชุด package และ role สำหรับ workspace
Preset roleรายชื่อผู้เชี่ยวชาญที่ DevBuddy ควรพิจารณา
Workspaceที่เก็บการเลือก profile ที่ .devbuddy/packages.json

ก่อนเริ่ม: เปิด Terminal ในที่ถูกต้อง

คำสั่ง profile อยู่ใน repository ของ DevBuddy ไม่ได้อยู่ในทุกโฟลเดอร์โครงการ เปิด Terminal แล้วเข้าไปที่ repository root ซึ่งมองเห็นทั้งโฟลเดอร์ profiles/ และไฟล์ scripts/profile_resolver.py ถ้าไม่มี checkout นี้ ให้ขอผู้ดูแลโครงการให้ path หรือ commit ที่อนุมัติ; อย่าดาวน์โหลด branch ที่เปลี่ยนตลอดเวลาเพื่อใช้กับงานจริง

ตรวจว่าคุณอยู่ถูกที่ 
pwd
ls profiles scripts/profile_resolver.py
python3 scripts/profile_resolver.py --list

ถ้าเห็นรายการ profile แปลว่าพร้อมแล้ว ทุกคำสั่งในหน้านี้เป็น preview โดยปริยาย เว้นแต่มี --apply ชัดเจน

ขั้นที่ 1: ดูรายการและเลือกให้ตรงงาน

ดู profile ทั้งหมด 
python3 scripts/profile_resolver.py --list
Profileใช้เมื่อ
product-deliveryทำ feature, website หรือ app: requirement, UX, architect, frontend/backend, QA และ review
cloud-operationsCI/CD, cloud, reliability, monitoring หรือ incident
data-aidata pipeline, analysis, model evaluation และ compliance
support-knowledgehelpdesk, FAQ, คู่มือ และการดูแล knowledge base
minimalอยากใช้ core อย่างเบาที่สุด

Profile ที่ขึ้นต้น data- เป็นความสามารถ database แยกต่างหากและต้องมี approval/credential แบบ least privilege; อย่าเลือกเพียงเพราะต้องการอ่านไฟล์ CSV หรือวิเคราะห์ข้อมูลทั่วไป

ขั้นที่ 2: ทดลองเลือก profile ก่อนติดตั้ง

แทน <host> ด้วย codex, claude-code หรือ opencode คำสั่งนี้แค่แสดง package และ role ที่จะใช้ ไม่สร้างและไม่แก้ไฟล์

Preview 
python3 scripts/profile_resolver.py product-delivery --platform <host>
# ตัวอย่างสำหรับ Codex
python3 scripts/profile_resolver.py product-delivery --platform codex

อ่านผลลัพธ์ก่อน: ตรวจชื่อ profile, platform, packages และ roles หากเห็น host ที่ไม่ตรงหรือ package ที่ไม่ต้องการ ให้หยุดและเลือก profile อื่น ไม่ต้องมีการ cleanup เพราะยังไม่มีอะไรถูกเขียน

เมื่อต้องการบันทึกผลลง workspace ให้แทน <workspace> ด้วยโฟลเดอร์ที่จะมี .devbuddy และรัน preview เดิมซ้ำพร้อม path ก่อน:

บันทึก profile ครั้งแรก 
python3 scripts/profile_resolver.py product-delivery \
  --platform <host> --devbuddy-root <workspace>/.devbuddy

python3 scripts/profile_resolver.py product-delivery \
  --platform <host> --devbuddy-root <workspace>/.devbuddy --apply

เฉพาะบรรทัดสุดท้ายที่มี --apply จะเขียน packages.json การเขียนเป็นแบบ atomic: ถ้าตรวจข้อมูลไม่ผ่าน จะไม่เหลือไฟล์ครึ่งเดียว

ขั้นที่ 3: เพิ่ม profile โดยไม่ลบของเดิม

ใช้เมื่อ workspace เดิมทำ product อยู่แล้วและต้องการเพิ่มงาน data/AI เป็นต้น Resolver จะเก็บ dependency ที่ทั้งสอง profile ใช้ร่วมกัน และเก็บ host ที่ active อยู่ไว้

เพิ่ม data-ai 
python3 scripts/profile_resolver.py --add-profile data-ai \
  --platform <host> --devbuddy-root <workspace>/.devbuddy

python3 scripts/profile_resolver.py --add-profile data-ai \
  --platform <host> --devbuddy-root <workspace>/.devbuddy --apply

ดูส่วน added, retained และ removed ใน preview ก่อนเสมอ ถ้าเปลี่ยน host โดยไม่ตั้งใจ ให้ยกเลิกและส่ง --platform ที่ถูกต้อง ไม่ควรแก้ JSON ด้วยมือ

ขั้นที่ 4: ถอน profile ที่ไม่ต้องใช้

การถอนจะลบเฉพาะ package หรือ role ที่ไม่มี profile อื่นต้องใช้ จึงปลอดภัยกว่าลบรายการในไฟล์เอง ตัวอย่างนี้ถอน data-ai แต่คง product-delivery ไว้

ถอน data-ai 
python3 scripts/profile_resolver.py --remove-profile data-ai \
  --platform <host> --devbuddy-root <workspace>/.devbuddy

python3 scripts/profile_resolver.py --remove-profile data-ai \
  --platform <host> --devbuddy-root <workspace>/.devbuddy --apply
Profile ไม่ใช่ plugin uninstallการถอน profile เปลี่ยนเฉพาะ composition ของ workspace ไม่ได้ลบ Codex/Claude/OpenCode plugin ออกจากเครื่อง และไม่ลบ task, knowledge หรือ secret ใต้ .devbuddy

ขั้นที่ 5: ตรวจสถานะหลังเพิ่มหรือถอน

ตรวจ composition ที่บันทึกไว้ 
python3 scripts/profile_resolver.py --status \
  --devbuddy-root <workspace>/.devbuddy

ตรวจว่า profiles ตรงตามที่ตั้งใจ, active platform ถูกต้อง และไม่มี package ที่ไม่ต้องการ ถ้าต้องย้อนกลับ ให้ใช้ --remove-profile สำหรับตัวที่เพิ่มล่าสุด แล้ว --add-profile ตัวที่ต้องการกลับ โดยทำ preview ทุกครั้ง

ขั้นที่ 6: เข้าใจว่า preset role ทำงานอย่างไร

หลังบันทึก profile แล้ว เวลาส่งงานปกติ เช่น $devbuddy ช่วยวางแผน feature นี้ หรือคำสั่ง DevBuddy ของ host อื่น Orchestrator จะเสนอ role ที่เกี่ยวข้อง คุณไม่ต้องเรียกทุก role เอง ตัวอย่าง product-delivery อาจใช้ Requirements Analyst เพื่อทำ acceptance criteria, Architect เพื่อออกแบบ, Frontend/Backend Engineer เพื่อทำงาน, QA เพื่อทดสอบ และ Code Reviewer เพื่อตรวจทาน

Profile ไม่บังคับให้ทุก role ทำงานทุกครั้ง และไม่ข้าม approval: DevBuddy ต้องบอกเหตุผล, scope, risk และจุดอนุมัติก่อน dispatch งานที่มีผลกระทบ

ขั้นที่ 7: ใช้ preset กับ OpenCode

หลังเลือก profile สำหรับ OpenCode แล้ว ให้ materialize เฉพาะ preset ที่ต้องใช้ลงใน project ก่อน คำสั่งแรก preview, คำสั่งที่สองเขียน agent file และจะไม่เขียนทับของเดิม

OpenCode agent preset 
python3 <plugin-directory>/scripts/materialize_agents.py \
  --preset product-delivery --project-root <project>

python3 <plugin-directory>/scripts/materialize_agents.py \
  --preset product-delivery --project-root <project> --apply

เลือก cloud-operations, data-ai หรือ support-knowledge ได้เช่นกัน ไฟล์จะอยู่ใต้ <project>/.opencode/agents/devbuddy/ อ่าน คู่มือ OpenCode หากต้องการขั้นติดตั้ง host

ปัญหาที่พบบ่อย

ข้อความหรืออาการทำอย่างไร
ไม่พบ profileรัน --list จาก repository root และสะกดชื่อให้ตรง
profile ไม่รองรับ hostตรวจ --platform; เลือก host plugin ให้เสร็จก่อน
ไม่พบ workspaceสร้าง workspace ตาม ขั้น workspace หรือใช้ path ที่ถูกต้อง
กลัวว่าคำสั่งจะเปลี่ยนไฟล์เอา --apply ออก; resolver จะเป็น dry run
OpenCode บอกว่าไฟล์ agent มีอยู่อย่า overwrite; ตรวจไฟล์เดิม เลือก role อื่น หรือให้ผู้ดูแลตัดสินใจว่าจะย้าย/ลบ

หลังตั้ง profile แล้วทำอะไรต่อ

ส่งคำขอเล็ก ๆ ให้ DevBuddy เสนอแผนและ role ที่จะใช้ก่อน เมื่อแผนถูกต้องจึงอนุมัติขอบเขตงาน อ่าน Task และ knowledge เมื่อต้องเก็บหลักฐานระยะยาว และเปิด แก้ปัญหา หากคำสั่งหยุดพร้อม error
