เริ่มต้นใช้งาน

ติดตั้ง adapter, สร้าง multi-project workspace, seed runtime tools และตรวจสอบงานแรก

Manual 0.4.4Dry-run ก่อน

สิ่งที่ต้องมี

ใช้ Python 3.9 ขึ้นไป, config root ของ adapter ที่จะติดตั้งซึ่งอนุมัติแล้ว และสิทธิ์เข้าถึง workspace กับทุก repository ที่จะลงทะเบียน หากมี knowledge repository แยกควร backup และ version control ไว้

ติดตั้ง adapter

ดูรายการไฟล์ก่อน apply และ installer จะปฏิเสธ collision ที่ไม่ใช่ DevBuddy

Codex 
python3 devbuddy-codex/scripts/install_codex_adapter.py
python3 devbuddy-codex/scripts/install_codex_adapter.py --apply
Claude Code 
python3 devbuddy-claude/scripts/install_claude_adapter.py
python3 devbuddy-claude/scripts/install_claude_adapter.py --apply
ขอบเขต runtimeInstalled skill จะมี Python ที่รันได้เฉพาะ initializer; runtime tools จะถูกคัดลอกไป `.devbuddy/tools/`

สร้าง workspace

เลือกตำแหน่ง `.devbuddy` ได้เอง และใช้ `--project ID=PATH` ซ้ำสำหรับ FE, BE หรือ service อื่น

Preview แล้ว apply 
python3 <installed-skill>/scripts/init_project_memory.py \
  --devbuddy-root /path/to/knowledge-repo/.devbuddy \
  --project fe=../frontend \
  --project be=../backend \
  --dry-run

Relative path resolve จาก parent ของ `.devbuddy`; path ต้องมีอยู่, ไม่ซ้ำ และไม่อยู่ภายใน `.devbuddy`

ตั้งค่า settings

เติม orchestration policy หลัง initializer สร้าง registry และ memory locator แล้ว

settings.yaml 
schema_version: 1
workspace:
  projects:
    fe:
      path: ../frontend
    be:
      path: ../backend
memory_root: knowledge-base
orchestration:
  max_concurrency: 2
  task_timeout_seconds: 900
  retry_limit: 1
  adapter_profiles: [claude, codex]
  approved_models: [...]
  approved_effort_levels: [...]

ตั้งครั้งเดียวพอ Claude และ Codex จะเลือก entry ที่ tag ตรงกับ adapter ที่กำลังรันให้อัตโนมัติ จึงไม่มีค่า active adapter ที่ต้องสลับเอง

ตรวจและ bootstrap

Project-local tools 
python3 .devbuddy/tools/validate_project_settings.py .devbuddy/settings.yaml
python3 .devbuddy/tools/bootstrap_knowledge.py --devbuddy-root .devbuddy --project-id fe --dry-run
python3 .devbuddy/tools/bootstrap_knowledge.py --devbuddy-root .devbuddy --project-id fe --apply
python3 .devbuddy/tools/validate_knowledge.py --devbuddy-root .devbuddy

ทำซ้ำกับ `be`; review observations ก่อน apply และ bootstrap จะไม่สร้าง typed canonical entity เอง

สร้าง task แรก

Workspace task 
python3 .devbuddy/tools/task_memory.py init \
  --devbuddy-root .devbuddy \
  --project-id fe --project-id be \
  --task-id checkout-001

ใช้ ledger เดียวสำหรับงานข้าม repository แล้วอ่าน Task และ knowledge ต่อ
