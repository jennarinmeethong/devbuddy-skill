เริ่มใช้ทีละขั้น

ทำตามลำดับนี้ครั้งละหนึ่งขั้น คุณสามารถหยุดหลังส่ง prompt แรกได้เลย; workspace และ preset เป็นสิ่งที่เพิ่มภายหลังเมื่อเริ่มทำงานจริง

Manual 0.4.6ไม่ต้องเขียนโค้ดก่อนดูผลก่อนเปลี่ยนไฟล์

ขั้นที่ 0: เตรียมสิ่งที่ต้องมี

  1. เลือกแอป AI ที่คุณใช้แล้วเพียง หนึ่ง ตัว: Codex, Claude Code หรือ OpenCode
  2. เปิด Terminal ของเครื่อง หรือขอผู้ดูแลโครงการรันคำสั่งติดตั้งให้ หากคุณไม่คุ้นเคยกับ Terminal
  3. เตรียมโฟลเดอร์โครงการที่ต้องการทำงาน และอย่าใส่รหัสผ่านหรือข้อมูลลูกค้าจริงในคำขอ
  4. ถามผู้ดูแลหา approved release tag หรือ commit SHA ของ DevBuddy ก่อนติดตั้ง ค่านี้จะใช้แทน <approved-ref> ด้านล่าง ห้ามใช้ branch ที่เปลี่ยนได้ เช่น main กับงานจริง
ยังไม่มี host หรือสิทธิ์ติดตั้ง?หยุดที่นี่ได้อย่างปลอดภัย ส่งลิงก์หน้านี้ให้ผู้ดูแล แล้วกลับมาที่ขั้น 2 หลังติดตั้งเสร็จ

ขั้นที่ 1: เลือกและติดตั้ง host

เลือกเฉพาะบล็อกเดียวที่ตรงกับแอปของคุณ ทุกคำสั่งต้องรันใน Terminal และให้แทน <approved-ref> ก่อนกด Enter หากคำสั่งถามยืนยัน ให้ตรวจชื่อ plugin และแหล่งที่มาก่อนตอบตกลง

ใช้ Codex

Codex 
codex plugin marketplace add jennarinmeethong/devbuddy-skill --ref <approved-ref> --json
codex plugin add devbuddy-codex@devbuddy --json
# ปิดหรือเริ่ม Codex task ใหม่ แล้วพิมพ์:
$devbuddy ช่วยวางแผนงานแรกของฉัน

ใช้ Claude Code

Claude Code 
claude plugin marketplace add jennarinmeethong/devbuddy-skill@<approved-ref> --scope user --sparse .claude-plugin plugin/devbuddy-claude-code
claude plugin install devbuddy-claude-code@devbuddy --scope user
# เปิด Claude Code แล้วพิมพ์:
/reload-plugins
/devbuddy-claude-code:devbuddy ช่วยวางแผนงานแรกของฉัน

ใช้ OpenCode

OpenCode 
opencode plugin 'github:jennarinmeethong/devbuddy-skill#<approved-ref>::path:plugin/devbuddy-core/opencode' --global
# ใช้ --global เพื่อติดตั้งให้ทุกโครงการ หรือเอาออกเพื่อติดตั้งเฉพาะโครงการปัจจุบัน

OpenCode ใช้ agent preset ภายในโครงการ จึงให้ทำขั้น 4 ก่อนเลือก agent ใน UI ของ OpenCode หากติดตั้งแล้วไม่เห็น plugin หรือ agent ให้ดู การแก้ปัญหา plugin

ขั้นที่ 2: ส่งคำขอแรก

ข้อความที่ดีไม่ต้องใช้ศัพท์ AI ให้บอกเพียง 4 เรื่อง: เป้าหมาย, สิ่งที่มีอยู่, ข้อจำกัด และ ผลลัพธ์ที่อยากได้ คัดลอกตัวอย่างนี้แล้วแก้ไขข้อความในวงเล็บได้

ตัวอย่าง prompt ที่ปลอดภัย 
ฉันต้องการ [ผลลัพธ์] สำหรับ [ผู้ใช้หรือโครงการ]
ตอนนี้มี [ไฟล์ / ระบบ / ข้อมูลที่เกี่ยวข้อง]
ข้อจำกัดคือ [เวลา งบ กฎ หรือสิ่งที่ห้ามทำ]
โปรดเริ่มจากสรุปความเข้าใจ ถามคำถามที่จำเป็น
แล้วเสนอแผนแบบยังไม่แก้ไฟล์หรือเรียกบริการภายนอก
บอกด้วยว่าต้องใช้บทบาทใด เหตุผล ความเสี่ยง และจุดที่ต้องขออนุมัติ

ตัวอย่างงานแรก: “ฉันต้องการหน้า login สำหรับเว็บภายใน มี React อยู่แล้ว ต้องรองรับมือถือ ยังห้ามแก้ไฟล์ ช่วยสรุป requirement และเสนอแผนพร้อม test ที่ควรมี”

ขั้นที่ 3: เลือก preset เมื่อรู้ประเภทงาน

preset คือรายการ role ที่ DevBuddy ควรคำนึงถึง ไม่ได้เปิดสิทธิ์ใหม่ ไม่ทำให้ AI เข้าถึง production และไม่เริ่มงานแทนคุณ ถ้าเพียงอยากทดลอง ไม่ต้องเลือก preset ก็ได้

presetเหมาะกับบทบาทหลัก
product-deliveryสร้างหรือปรับ productrequirements, UX, architect, frontend/backend, QA, code review
cloud-operationsCI/CD, cloud, reliability, incidentDevOps, cloud, SRE, vulnerability, incident response
data-aipipeline, analysis, AI evaluationdata pipeline, analyst, evaluator, compliance
support-knowledgeคู่มือ, FAQ, supporthelpdesk, knowledge base, requirements

หากทีมมี checkout ของ repository นี้ ให้เปิด Terminal ที่ repository root แล้วตรวจรายการก่อน:

ดูและเลือก profile 
python3 scripts/profile_resolver.py --list
python3 scripts/profile_resolver.py product-delivery --platform codex
# เปลี่ยน codex เป็น claude-code หรือ opencode ตาม host ของคุณ

คำสั่งนี้เป็น preview เท่านั้น ยังไม่เปลี่ยนไฟล์ ดูผลแล้วค่อยทำขั้น workspace ด้านล่าง หากต้องการบันทึก composition จริง

ขั้นที่ 4: สร้าง workspace เมื่อทำงานต่อเนื่อง

ข้ามขั้นนี้ได้สำหรับคำถามครั้งเดียว ใช้เมื่อหลายคนหรือหลาย agent ทำงานกับโครงการเดียวกัน, งานข้าม repository หรือคุณอยากเก็บ task และความรู้ที่ตรวจแล้ว คำสั่งแรกเป็น dry run; คำสั่งที่สองจึงสร้างโฟลเดอร์ .devbuddy

สร้าง workspace แบบ preview ก่อน 
python3 <installed-plugin-root>/scripts/init_project_memory.py \
  --devbuddy-root /path/to/team-workspace/.devbuddy \
  --project app=/path/to/your-project --dry-run

python3 <installed-plugin-root>/scripts/init_project_memory.py \
  --devbuddy-root /path/to/team-workspace/.devbuddy \
  --project app=/path/to/your-project

<installed-plugin-root> คือโฟลเดอร์ที่ plugin ถูกติดตั้งไว้ ไม่ใช่โฟลเดอร์โครงการของคุณ หากหาไม่เจอ ให้ขอผู้ดูแลช่วยชี้ path แทนการเดา หลังสร้างแล้วตรวจ settings ด้วย python3 .devbuddy/tools/validate_project_settings.py .devbuddy/settings.yaml จากโฟลเดอร์ team workspace

ขั้นที่ 5: อ่านผลและอนุมัติอย่างถูกจุด

ก่อนให้ทำงานต่อ ให้ตรวจคำตอบ 5 ข้อ: เป้าหมายตรงหรือไม่, มีไฟล์/ระบบใดจะถูกแตะ, role แต่ละตัวทำอะไร, จะตรวจผลอย่างไร, และต้องขออนุมัติช่วงใด ถ้าขาดข้อใด ให้ตอบกลับว่า “อธิบายข้อนี้ให้คนไม่เชี่ยวชาญเข้าใจ และยังอย่าทำการเปลี่ยนแปลง”

เมื่อแผนถูกต้อง ค่อยระบุขอบเขตชัดเจน เช่น “อนุมัติให้แก้เฉพาะโฟลเดอร์ src/login และรัน unit test เท่านั้น ยังห้าม deploy หรือส่งข้อมูลออกนอกเครื่อง”

ขั้นที่ 6: หยุดและถามเมื่อเจอสัญญาณนี้

  • คำสั่งจะลบไฟล์, เขียน database, deploy, ส่งข้อมูลออก หรือมีค่าใช้จ่าย
  • คุณไม่รู้ว่า role, tool หรือคำสั่งกำลังทำอะไร
  • ระบบขอ secret, API key หรือข้อมูลลูกค้าจริง
  • ผลลัพธ์ขัดกับสิ่งที่คุณตั้งใจไว้

ให้ตอบว่า “หยุดก่อน อธิบายผลกระทบ ทางเลือก และวิธีย้อนกลับเป็นภาษาไทยง่าย ๆ” แล้วตัดสินใจหลังเห็นข้อมูลครบ

ติดขัดตรงไหน

ไม่เห็น plugin หลังติดตั้ง: เปิด แก้ปัญหา plugin. ไม่เข้าใจ workspace: อ่าน Workspace. ต้องการติดตั้งหรืออัปเดตจาก Git: อ่าน Git install. ต้องใช้ database: อ่าน Database profiles ก่อนเสมอ

ขั้นต่อไป

หลัง prompt แรกสำเร็จ ให้เลือกงานเล็กหนึ่งงานและให้ DevBuddy แสดงแผนก่อน จากนั้นค่อยเปิดใช้ preset หรือ workspace ตามจำเป็น ไม่จำเป็นต้องเปิดทุกความสามารถตั้งแต่วันแรก
