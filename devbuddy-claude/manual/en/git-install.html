Install from Git

Use an approved release tag or full commit SHA. Do not use a mutable branch in production.

Install the host adapter

# Codex
codex plugin marketplace add jennarinmeethong/devbuddy-skill --ref v1.0.2 --json
codex plugin add devbuddy-codex@devbuddy --json

# Claude Code
claude plugin marketplace add jennarinmeethong/devbuddy-skill@v1.0.2 --scope user --sparse .claude-plugin plugin/devbuddy-claude-code
claude plugin install devbuddy-claude-code@devbuddy --scope user

# OpenCode
opencode plugin 'github:jennarinmeethong/devbuddy-skill#v1.0.2::path:plugin/devbuddy-core/opencode' --global

Replace v1.0.2 with the approved release tag or full commit SHA. Reload Claude Code after installation and start a fresh Codex task after an install or update.

Materialize a database adapter

Database execution is optional and Tier 2. Clone the same approved release, initialize the workspace, preview the operation, then explicitly apply it.

git clone --depth 1 --branch v1.0.2 https://github.com/jennarinmeethong/devbuddy-skill.git devbuddy-release
python3 devbuddy-release/scripts/workspace.py init --devbuddy-root <workspace>/.devbuddy --apply
python3 devbuddy-release/scripts/materialize_database_adapter.py --devbuddy-root <workspace>/.devbuddy --database-id billing --engine postgresql
python3 devbuddy-release/scripts/materialize_database_adapter.py --devbuddy-root <workspace>/.devbuddy --database-id billing --engine postgresql --apply

The materializer publishes a self-contained executable and writes only a read-only manifest and non-secret template below .devbuddy/tools/databases/billing/. It refuses to overwrite an existing adapter. Copy the template to the local, git-ignored appsettings.json yourself and provide a least-privilege read-only principal.

Verify

Resolve the desired data profile for the host, verify the workspace, and retain the host's normal approval prompts for every target-specific Tier 2 database request.
