Workspace

รวม knowledge, task coordination และ tools ไว้ด้วยกัน ขณะที่ source code ยังอยู่ใน repository ของมันเอง

Manual 0.4.6หลาย project

เลือกตำแหน่ง workspace

`.devbuddy` ไม่จำเป็นต้องอยู่ใน application repository เดียว สามารถอยู่ข้าง FE/BE หรือใน dedicated knowledge Git repository

workspace/
├── frontend/
├── backend/
└── knowledge-repo/
    └── .devbuddy/
        ├── settings.yaml
        ├── knowledge-base/
        ├── tasks/
        └── tools/

ลงทะเบียนหลาย project

Project ID เป็นชื่อคงที่ที่ใช้ใน settings, bootstrap, metadata และ task scope

settings.yaml 
workspace:
  projects:
    fe:
      path: ../frontend
    be:
      path: ../backend
memory_root: knowledge-base

Initializer จะ reject path ที่ไม่มีอยู่, ID ซ้ำ, path ซ้ำ หรือ path ที่อยู่ภายใน `.devbuddy`

แต่ละ path ใช้ทำอะไร

Pathหน้าที่
.devbuddy/knowledge-base/Shared canonical knowledge และ observations ที่ review ได้
.devbuddy/tasks/Ledger, slice record, reservation และ analysis ระดับ workspace
.devbuddy/tools/Python runtime ที่ initializer คัดลอกมา
.devbuddy/settings.yamlProject registry และ orchestration policy
Source repositoriesFE, BE หรือ source อื่น; specialist เขียนได้เฉพาะ scope ที่อนุมัติ

Dedicated knowledge repository

Commit `.devbuddy/` ใน knowledge repository และใช้ relative source paths เพื่อให้ clone แล้วย้ายเครื่องได้สะดวก หากต้องใช้ absolute path ให้เก็บเป็น local override ตาม policy ของทีม

เหตุผลด้าน antivirusหลัง bootstrap Python runtime จะรันจาก workspace ที่ scanner รู้จัก ส่วน global skill ใช้เฉพาะ initializer ครั้งแรก

การระบุ project ใน knowledge

Core files และ typed folders อยู่ใต้ `knowledge-base/` ทุก entity ต้องมี immutable ID และ `project_ids` ที่ไม่ว่าง ข้อเท็จจริงร่วมอาจระบุทั้ง `fe` และ `be` พร้อม evidence path ของ repository ต้นทาง
