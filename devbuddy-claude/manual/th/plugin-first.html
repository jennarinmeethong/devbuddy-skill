การแจกจ่ายแบบ Plugin-first

ติดตั้ง Plugin หรือ profile ที่เป็น native ของ host เพียงชุดเดียว ส่วน portable core ถูก bundle เป็น dependency และไม่ต้องติดตั้ง core skill แยก

Claude Code: lifecycle ของ marketplace

catalog ของ marketplace อยู่ที่ .claude-plugin/marketplace.json ให้ validate package, เพิ่ม marketplace และ Plugin ใน scope เดียวกัน, ตรวจ discovery, refresh session แล้วเรียกคำสั่งที่มี namespace ใช้ user สำหรับการติดตั้งของผู้ใช้ในเครื่อง และใช้ project หรือ local เฉพาะเมื่อเป็นขอบเขตที่ตั้งใจ

ติดตั้งและตรวจสอบ 
claude plugin validate plugin/devbuddy-claude-code
claude plugin marketplace add . --scope user
claude plugin marketplace list
claude plugin install devbuddy-claude-code@devbuddy --scope user --yes
claude plugin list --json
# ใน Claude Code
/reload-plugins
/devbuddy-claude-code:devbuddy <task>

Claude Code จะ namespace skill ของ Plugin ดังนั้น /devbuddy แบบไม่มี namespace เป็นของ legacy standalone compatibility เท่านั้น

Codex: lifecycle ของ Plugin และ profile

Codex ติดตั้ง Plugin จาก marketplace snapshot ที่ตั้งค่าไว้ repository นี้มี marketplace catalog ที่ .agents/plugins/marketplace.json ให้เพิ่ม root ของ repository แล้วติดตั้ง devbuddy-codex@devbuddy หากใช้ marketplace อื่น ให้ใช้ root และชื่อที่คำสั่ง list แสดง

ค้นหา, ติดตั้ง, resolve และเรียกใช้ 
codex plugin marketplace list --json
codex plugin marketplace add . --json
codex plugin list --available --json
codex plugin add devbuddy-codex@devbuddy --json
codex plugin list --json
python3 scripts/profile_resolver.py profiles/codex.yaml --platform codex --dry-run
python3 scripts/profile_resolver.py profiles/codex.yaml --platform codex --apply --devbuddy-root <workspace>/.devbuddy
# เปิด Codex thread ใหม่
$devbuddy <task>

Codex adapter ส่งค่า model และ reasoning_effort ที่อนุมัติแล้วให้ specialist ทุกครั้ง ถ้า host ส่งสองค่านี้ไม่ได้ งานจะหยุดเป็น waiting_user

Update, disable และ rollback

Claude Code lifecycle 
claude plugin marketplace update devbuddy
claude plugin update devbuddy-claude-code@devbuddy
claude plugin list --json
# ใน Claude Code
/reload-plugins
claude plugin uninstall devbuddy-claude-code@devbuddy --keep-data

สำหรับ marketplace ใน repository นี้ซึ่งเป็น local ให้ update Plugin cachebuster แล้ว add package ใหม่ ส่วน Git marketplace ต้อง upgrade ด้วย marketplace name ของตัวเองก่อน add ใหม่:

# local repository marketplace
codex plugin add devbuddy-codex@devbuddy --json
codex plugin list --json
# Git marketplace เท่านั้น
codex plugin marketplace upgrade <marketplace>
codex plugin remove devbuddy-codex@devbuddy

ใช้ codex plugin marketplace remove devbuddy เฉพาะเมื่อไม่มี Plugin ที่ยังใช้ source นั้นแล้ว และเปิด thread ใหม่หลังมีการเปลี่ยนแปลง การ rollback คือกลับไปใช้ package/profile version ที่อนุมัติแล้ว ส่วน state ใต้ .devbuddy/ ไม่ใช่ package data

ความเข้ากันได้กับ standalone เดิม

DevBuddy 1.x ยังเก็บ installer เดิมเป็น migration-aware shim โดยจะแสดง Plugin path เป็นค่าเริ่มต้น ไม่ลบไฟล์ host และหยุดเมื่อเจอ unknown-file conflict ใช้เพื่อดูสถานะหรือรักษา standalone เดิมเท่านั้น

รายงานแบบอ่านอย่างเดียว 
python3 devbuddy-claude/scripts/install_claude_adapter.py --migration-report
python3 devbuddy-codex/scripts/install_codex_adapter.py --migration-report

หลัง migrate ไป Plugin สำเร็จ ให้ถอน standalone skill ผ่าน UI ของ host หรือการย้ายไป backup ที่ตรวจสอบและกู้คืนได้ ห้ามลบ .devbuddy/, task ledger, canonical knowledge หรือ secret ในเครื่อง

Ownership และขอบเขตความปลอดภัย

  • package artifact เป็นเจ้าของ host skill, generated agents, references, schemas, templates และ delivery metadata
  • .devbuddy/ เป็นเจ้าของ settings, task ledger, tools, observations และ canonical knowledge ของ workspace
  • secret อยู่ในไฟล์ local ที่อ้างจาก template ซึ่ง commit ได้; credential และ project state ห้ามอยู่ใน Plugin artifact
  • database เป็น Tier 2 และ Plugin-owned ต้องมี core package, engine adapter, manifest, read-only principal และ target-specific approval
  • การ install, update, migrate และ remove ต้องเริ่มจาก dry-run หรือ discovery check และหยุดเมื่อพบ conflict ที่ไม่รู้จัก

การตรวจ release และ host

เมื่อแก้ repository ให้รัน source-preservation, package-drift, manual-conformance, secret-exclusion และ release validation สำหรับ Claude host ให้ validate manifest, install จาก marketplace ที่ตั้งใจใช้, รัน claude plugin list --json, refresh และทดสอบ namespaced invocation แบบอ่านอย่างเดียว สำหรับ Codex ให้ยืนยันทั้ง codex plugin marketplace list --json และ codex plugin list --json แล้วเปิด thread ใหม่
