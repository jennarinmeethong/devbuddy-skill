Manual 0.4.6Plugin-firstไทย / English

เริ่มจาก distribution ปัจจุบัน

ติดตั้ง Plugin หรือ profile แบบ native ของ host เพียงชุดเดียว แล้วเรียก entrypoint ของ adapter อย่าง explicit โดย portable policy devbuddy-core จะถูก bundle เป็น dependency ไม่ต้องติดตั้ง standalone skill ซ้ำ

เส้นทางแนะนำอ่าน Plugin-first ต่อด้วย เริ่มต้นใช้งาน แล้วอ่าน Workspace สำหรับงานหลาย repository

ลำดับการอ่าน

  1. Plugin-first — package ID, marketplace/profile lifecycle, migration และ ownership
  2. เริ่มต้นใช้งาน — install, initialize, configure, validate และสร้าง task
  3. Workspace — เลือก .devbuddy, ลงทะเบียน project และจัด knowledge
  4. Scripts — runtime ที่ package เป็นเจ้าของและ runtime ใน workspace
  5. Task และ knowledge — ประสาน task และ owner-controlled knowledge
  6. Migration — ย้าย layout เดิมและ upgrade tools อย่างปลอดภัย
  7. แก้ปัญหา — แก้ Plugin, workspace และ runtime errors

หลักการออกแบบ

  • Plugin เป็นเจ้าของ host payload ส่วน .devbuddy/ เป็นเจ้าของ state ของ workspace
  • Python runtime ทำงานจาก project-local tools ที่ตรวจ hash ใน manifest แล้ว
  • Knowledge ต้อง explicit, มี evidence และระบุ project ID
  • ต้องมี dry-run, approval และ validation gate ก่อน write
  • specialist ห้ามแทน owner แบบเงียบ ๆ, bypass approval หรือเขียน canonical knowledge จาก scan ที่ยังไม่ review
