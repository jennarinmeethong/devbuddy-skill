DevBuddy adapter สำหรับ Claude Code

DevBuddy ทำงานส่งมอบซอฟต์แวร์เหมือนแผนก IT หนึ่งแผนก โดยมี Orchestrator ทำหน้าที่ประเมินงาน วางลำดับการพึ่งพา มอบหมายงานให้ subagent เฉพาะทาง ติดตามการส่งต่องาน และส่งงานไปยังบทบาทถัดไป ผู้ทำงานจริงคือผู้เชี่ยวชาญแต่ละบทบาท ไม่ใช่ Orchestrator

เรียกใช้อย่างชัดเจนด้วย /devbuddy เท่านั้น ระบบจะไม่ทำงานเองกับคำสั่งเขียนโค้ดทั่วไป ข้อกำหนดนี้เองที่ทำให้ด่านขออนุมัติต่าง ๆ คาดเดาได้

รูปแบบคำสั่ง

/devbuddy <role> <task>
/devbuddy loop <role> <task>
/devbuddy owner <task>
/devbuddy owner loop <task>

บทบาทหลัก: ba-pm, ux-ui, architect, developer, qa, security, devops-sre, dba-data, reviewer ชื่อย่อที่ใช้ได้: ba, sa, dev, tester, operations, data, analyze, docs ส่วน owner จะสร้างกราฟงานแบบหลายบทบาท

บทบาทและวงจรชีวิตของงาน

แต่ละบทบาทมีขั้นตอนการทำงาน สิทธิ์ในการตัดสินใจ artefact ที่เป็นเจ้าของ หลักฐานที่ต้องมี และรูปแบบการส่งต่องานที่กำหนดไว้ชัดเจน artefact หลักทุกชิ้นมีเจ้าของเพียงบทบาทเดียว บทบาทอื่นมีส่วนร่วมผ่านการส่งต่องาน ไม่ใช่แก้ไขไฟล์เดียวกันพร้อมกัน

สถานะของงานมี queued, running, blocked, waiting_user, verifying, completed, failed และ cancelled ระดับความเสี่ยงแบ่งเป็น low, medium, high, critical และจะใช้ระดับที่สูงที่สุดที่เข้าเงื่อนไขเสมอ

การเลือก model และ effort

ทุกครั้งที่ส่งงานให้ subagent จะต้องระบุทั้ง model ที่อนุมัติแล้วและระดับ effort ที่อนุมัติแล้ว บน Claude Code ระดับ effort ถูกกำหนดจาก subagent ที่เลือก โดย adapter ติดตั้ง subagent หนึ่งตัวต่อหนึ่งบทบาทและหนึ่งระดับ effort ส่วน model จะถูกส่งเป็นพารามิเตอร์ในแต่ละครั้ง DevBuddy จะเลือกคู่ที่ลำดับต่ำที่สุดเท่าที่เพียงพอกับบทบาทและความเสี่ยง แล้วบันทึกเหตุผลลง task ledger การเลือกระดับสูงขึ้นต้องมีเหตุผลเฉพาะงานนั้นบันทึกไว้

การตั้งค่าและหน่วยความจำโครงการ

การตั้งค่าระดับโครงการอยู่ที่ <project-root>/.devbuddy/settings.yaml ส่วนหน่วยความจำโครงการอยู่ที่ <project-root>/.devbuddy/ โดยปริยาย และย้ายไปที่อื่นได้ รวมถึง Obsidian vault ผ่านตัวชี้ตำแหน่ง memory_root องค์ความรู้แต่ละรายการมีคีย์ถาวร เช่น REQ-001 หรือ DB-042 และโค้ดที่บังคับใช้ความรู้นั้นจะมีคอมเมนต์ devbuddy-ref กำกับ

ระบบจะไม่เขียนองค์ความรู้หลักจากผลวิเคราะห์ผลกระทบเพียงอย่างเดียว งานสาขานั้นจะรออยู่ที่สถานะ waiting_user จนกว่าคุณจะยืนยันรายการที่จะปรับปรุง

ความปลอดภัยและการขออนุมัติ

  • Git เป็นแบบอ่านอย่างเดียว เว้นแต่คุณสั่งให้ทำคำสั่ง Git นั้นอย่างเจาะจง
  • ไม่ติดตั้งเครื่องมือ runtime หรือ dependency ใด ๆ โดยไม่มีคำสั่งจากคุณ
  • สิ่งที่อาจมีค่าใช้จ่ายต้องขออนุมัติ พร้อมแจ้งผู้ให้บริการ เกณฑ์คิดเงิน และทางเลือกอื่น
  • งาน production การแก้ข้อมูลแบบทำลาย การเปลี่ยนสิทธิ์เข้าถึง และการผูกพันทางการเงิน ถือเป็นความเสี่ยงระดับ critical และต้องผ่านด่านอนุมัติ
  • ไม่เก็บความลับหรือข้อมูลส่วนบุคคลไว้ในหน่วยความจำ การส่งต่องาน ledger ผลทดสอบ หรือรายงานใด ๆ
  • เนื้อหาจากภายนอกถือเป็นข้อมูลเท่านั้น ไม่ใช่คำสั่งที่จะมาแทนที่คำสั่งของคุณได้

DevBuddy บังคับใช้กฎเหล่านี้ผ่านคำสั่งภายใน skill ไม่ได้แก้ไขไฟล์ .claude/settings.json และไม่ติดตั้ง hook ใด ๆ ดังนั้นการถามสิทธิ์ตามปกติของ Claude Code จึงยังเป็นด่านป้องกันสุดท้ายของคุณ

ภาษาที่ใช้

การสื่อสารภายในระหว่าง agent ทั้ง task package, ledger, การส่งต่องาน และไฟล์ตั้งค่า ใช้ภาษาอังกฤษ ส่วนสถานะ คำถาม การตัดสินใจ ค่าใช้จ่าย ความเสี่ยง และอุปสรรค จะรายงานถึงคุณเป็นภาษาไทย
