Plugin หายหรือค้นหาไม่พบ

ให้แยก marketplace (source ที่ตั้งค่าไว้) ออกจาก Plugin (package ที่หาเจอหรือติดตั้งแล้ว) รายการ Plugin ที่ว่างมักเกิดจาก marketplace source หาย, stale หรือผิด ไม่ใช่เหตุให้ติดตั้ง legacy skill กลับมา

claude plugin marketplace list
claude plugin list --json
# หรือบน Codex
codex plugin marketplace list --json
codex plugin list --available --json

สำหรับ Claude Code ใช้ /reload-plugins หลัง install/update แล้วเรียก /devbuddy-claude-code:devbuddy ส่วน Codex ให้เปิด thread ใหม่ อย่าติดตั้ง bare legacy skill เพื่อแก้ปัญหา namespaced Plugin

รายการ Plugin ว่างหรือหา package ไม่พบ

ทำตาม flow ของ host ให้ตรงกัน และรักษา package ID, marketplace name กับ install scope ให้ถูกต้อง หยุดหาก source ไม่ใช่ที่ทีมอนุมัติ เพราะ source ที่เดาเองอาจติดตั้ง package ผิดตัว

Claude Code

  1. ตรวจว่า repository มี .claude-plugin/marketplace.json, validate package และ list marketplace
  2. ถ้าไม่มี devbuddy ให้เพิ่ม source ที่อนุมัติด้วย scope เดียวกับ Plugin
  3. ติดตั้ง selector และ scope ที่ถูกต้อง, list ผลลัพธ์ แล้ว reload session
claude plugin validate plugin/devbuddy-claude-code
claude plugin marketplace list
claude plugin marketplace add . --scope user
claude plugin install devbuddy-claude-code@devbuddy --scope user --yes
claude plugin list --json
# ใน Claude Code
/reload-plugins
/devbuddy-claude-code:devbuddy <task>

หากยังไม่พบ ให้ปิดเปิด Claude Code ใหม่ ตรวจว่า marketplace path อ่านได้และ scope ตรงกับ install scope หาก Plugin ปรากฏแต่คำสั่งไม่มา ให้ reload อีกครั้งและใช้ namespace เต็ม อย่า fallback ไป /devbuddy เพราะเป็นคำสั่ง standalone เดิม

Codex

  1. สำหรับ repository นี้ ให้เพิ่ม root ของ repository เพราะ catalog อยู่ที่ .agents/plugins/marketplace.json
  2. list package ที่ available และยืนยัน devbuddy-codex@devbuddy
  3. ติดตั้ง, ตรวจ JSON ว่า installed/enabled, resolve profile แล้วเปิด thread ใหม่
codex plugin marketplace list --json
codex plugin marketplace add . --json
codex plugin marketplace list --json
codex plugin list --available --json
codex plugin add devbuddy-codex@devbuddy --json
codex plugin list --json
python3 scripts/profile_resolver.py profiles/codex.yaml --platform codex --dry-run
# ใน Codex thread ใหม่
$devbuddy <task>

หากมี marketplace แต่ไม่มี package ให้ตรวจว่า catalog ยังชี้ไปที่ ./plugins/devbuddy-codex และมี manifest อยู่ local clone จะเห็น source change โดยตรง; ให้ upgrade เฉพาะ marketplace ที่เพิ่มเป็น Git source: codex plugin marketplace upgrade <marketplace> ถ้า install แจ้ง unknown selector ให้รัน codex plugin marketplace list --json แล้วใช้ marketplace name ที่แสดง ถ้า Plugin ติดตั้งแล้วแต่ไม่มี $devbuddy ให้เปิด thread ใหม่ จากนั้นตรวจ profile dry-run ก่อน apply workspace changes

Entrypoint ใช้ไม่ได้

ใช้คำสั่ง explicit ของ host: Claude Code ใช้ /devbuddy-claude-code:devbuddy ส่วน Codex ใช้ $devbuddy ชื่อ /devbuddy แบบ bare เป็นของ legacy standalone เท่านั้น

ไม่แน่ใจเรื่อง migration หรือ uninstall

รัน compatibility shim แบบ report-only ซึ่งควรแสดง Plugin path โดยไม่แก้ไฟล์ host

python3 devbuddy-claude/scripts/install_claude_adapter.py --migration-report
python3 devbuddy-codex/scripts/install_codex_adapter.py --migration-report

backup path ของ legacy ให้ชัดก่อนถอน ใช้ option --keep-data ของ Claude ตอน rollback Plugin และอย่าลบ .devbuddy/

Installer หรือ initializer แจ้ง collision

เลือก config root ใหม่หรือ inspect target file installer และ shim จะแทนที่เฉพาะ DevBuddy artifact ที่รู้จัก และจะปฏิเสธไฟล์ unknown หรือไฟล์ที่ไม่เกี่ยวข้อง

Initializer ปฏิเสธ project

ตรวจว่า path มีอยู่ ไม่ซ้ำหลัง resolve และอยู่นอก .devbuddy relative path จะ resolve จาก parent ของ workspace root

Settings validation ไม่ผ่าน

ตรวจ memory_root: knowledge-base, project อย่างน้อยหนึ่งรายการ, path ที่มีอยู่, rank ของ model/effort ที่ไม่ซ้ำ, budget และ role/risk ที่อนุญาต

ตรวจ settings 
python3 .devbuddy/tools/validate_project_settings.py .devbuddy/settings.yaml

Tool upgrade ถูก block

ไฟล์ปัจจุบันต่างจาก manifest hash ให้ review diff แล้ว restore trusted version หรือจัดการ change ของ workspace เอง ห้าม force-replace unknown file

Bootstrap apply ไม่ผ่าน

อาจมี observation ของ project นี้อยู่แล้ว หรือไฟล์เป้าหมายไม่ใช่ scaffoldable ให้ review section เดิมและ promote fact ที่อนุมัติผ่าน owner protocol

Runtime หรือ antivirus เตือน

ยืนยันว่าคำสั่งใช้ .devbuddy/tools/ และ initializer ของ package เป็น bootstrap entrypoint เดียว เก็บ project-local tools ใน workspace repository ที่ scanner รู้จัก

Evidenceเก็บ warning, command และ path ใน task evidence อย่าปิด scanner หรือ bypass quarantine

Checklist ตรวจสอบ

  • Validate Plugin manifest และ host discovery
  • ถ้ารายการว่าง ให้เพิ่ม marketplace/package ใหม่ตาม flow ด้านบน
  • Refresh Claude หรือเปิด Codex thread ใหม่
  • Validate settings, knowledge และ task ledger
  • Review manifest hashes และ project-qualified scopes
  • บันทึก evidence และ rollback data
