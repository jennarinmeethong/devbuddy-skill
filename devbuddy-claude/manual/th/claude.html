Claude Code Skill adapter

สถานะ: ติดตั้งใช้งานได้แล้วที่ข้อกำหนดกลางเวอร์ชัน 0.1.1 รายการที่จำเป็นทั้งหมดใน devbuddy-claude/adapter-implementation-checklist.md มีสถานะ done

สิ่งที่ต้องมีก่อน

  • Claude Code ที่ติดตั้ง เข้าสู่ระบบ และใช้งานได้ในเครื่องเป้าหมาย
  • ความสามารถ subagent ที่รองรับฟิลด์ effort ใน frontmatter เพราะ adapter ใช้ฟิลด์นี้ในการระบุระดับ effort ของแต่ละการส่งงาน
  • Python 3 หากต้องการรันสคริปต์ตรวจสอบที่แถมมาด้วย สคริปต์ทั้งหมดใช้เฉพาะไลบรารีมาตรฐาน ไม่ต้องติดตั้งแพ็กเกจเพิ่ม
  • การอนุมัติจากคุณอย่างชัดเจน สำหรับการติดตั้ง การอัปเดต บัญชีแบบเสียเงิน หรือการใช้ model ใด ๆ

ตรวจสอบการติดตั้งด้วย claude doctor ได้ก็ต่อเมื่อคุณอนุญาตให้รันคำสั่งนั้นแล้ว อย่าสรุปว่าเครื่องมือถูกติดตั้งแล้วโดยไม่ตรวจสอบ

สิ่งที่จะถูกติดตั้ง

สิ่งที่ติดตั้งปลายทางหน้าที่
ตัว skill (SKILL.md, references/, roles/, templates/, schemas/, scripts/, manual/, settings.yaml)~/.claude/skills/devbuddy/ตัว Orchestrator และไฟล์นโยบายอ้างอิง
ไฟล์นิยาม subagent 27 ไฟล์ devbuddy-<role>-<effort>.md~/.claude/agents/ผู้เชี่ยวชาญ 9 บทบาท ในระดับ low, medium และ high

การติดตั้งระดับผู้ใช้ทำให้ใช้ DevBuddy ได้ทุกโครงการ แลกกับการที่รายการ devbuddy-* จำนวน 27 รายการจะปรากฏในรายชื่อ agent ของคุณ หากต้องการติดตั้งเฉพาะโครงการเดียว ให้ระบุ --claude-root ชี้ไปที่ .claude/ ของโครงการนั้นแทน

ขั้นตอนการติดตั้ง

  1. ยืนยันว่ารายการที่จำเป็นทุกข้อใน devbuddy-claude/adapter-implementation-checklist.md เป็น done
  2. ดูรายการไฟล์ทั้งหมดก่อน โดยค่าเริ่มต้นเป็นโหมดทดลอง ยังไม่มีการเขียนไฟล์จริง 
    python3 scripts/install_claude_adapter.py
  3. เมื่อรายการถูกต้องแล้วจึงติดตั้งจริง 
    python3 scripts/install_claude_adapter.py --apply
  4. เริ่มเซสชัน Claude Code ใหม่หรือรีเฟรช เพื่อให้ /devbuddy และ agent devbuddy-* ถูกโหลด

ตัวติดตั้งจะปฏิเสธการเขียนทับไฟล์ที่มีอยู่เดิมซึ่งไม่สามารถระบุได้ว่าเป็นไฟล์ของ DevBuddy กรณีชนกันเช่นนี้เป็นเรื่องที่คุณต้องตัดสินใจเอง ตัวติดตั้งจะไม่เดาแทน

อย่านำรหัสผ่าน connection string หรือข้อมูลส่วนบุคคล ไปใส่ในไฟล์ตั้งค่าหรือ prompt ของ Claude

การตั้งค่า

สร้างไฟล์ <project-root>/.devbuddy/settings.yaml ก่อนส่งงานครั้งแรก

schema_version: 1
memory_root: .devbuddy
orchestration:
  max_concurrency: 2
  task_timeout_seconds: 900
  retry_limit: 1
  approved_models:
    - id: haiku
      rank: 1
      allowed_roles: [developer, qa]
      allowed_risks: [low]
    - id: sonnet
      rank: 2
      allowed_roles: [ba-pm, architect, developer, qa, security, reviewer]
      allowed_risks: [low, medium, high]
  approved_effort_levels:
    - id: low
      rank: 1
      allowed_roles: [developer, qa]
      allowed_risks: [low]
    - id: medium
      rank: 2
      allowed_roles: [ba-pm, architect, developer, qa, security, reviewer]
      allowed_risks: [low, medium, high]

adapter มีค่าตั้งต้นให้แล้วเป็น haiku / sonnet / opus พร้อมระดับ low / medium / high เพื่อให้ใช้งานได้ทันที ให้ถือว่านี่คือขอบเขตที่อนุมัติไว้ ไม่ใช่การยกเว้นเรื่องค่าใช้จ่าย การเพิ่มผู้ให้บริการรายใหม่ การขยายรายการที่อนุญาต หรือการใช้ model ที่มีพฤติกรรมด้านความเป็นส่วนตัวต่างออกไป ล้วนเป็นการตัดสินใจเรื่องค่าใช้จ่ายครั้งใหม่ที่ต้องขออนุมัติ

max_concurrency, task_timeout_seconds และ retry_limit จงใจไม่มีค่าตั้งต้น เพราะเป็นการผูกพันเวลาและค่าใช้จ่ายของคุณ DevBuddy จึงเลือกที่จะถามแทนการเดา ถ้าไม่มีค่าเหล่านี้ ระบบจะไม่ส่งงาน

ความต่างจาก adapter ของ Codex

  • เรียกใช้ด้วย /devbuddy แทน $devbuddy
  • ระดับ effort มาจากฟิลด์ effort ของ subagent ที่เลือก ไม่ได้ส่งเป็นพารามิเตอร์ตอน dispatch การเลือกระดับ subagent จึงเท่ากับการเลือก effort
  • model ส่งเป็นพารามิเตอร์รายครั้งและมีสิทธิ์เหนือค่าใน frontmatter ไฟล์นิยาม agent จึงจงใจไม่ระบุ model ไว้
  • งานที่เป็นอิสระต่อกันจะถูกส่งเป็น Agent หลายคำสั่งในข้อความเดียว ภายใต้ max_concurrency และเพดานจำนวน subagent พร้อมกันของ Claude Code เอง

การตรวจสอบ

python3 scripts/validate_skill_metadata.py .
python3 scripts/check_adapter_conformance.py
python3 scripts/validate_manual.py manual
python3 scripts/run_scenarios.py tests/scenarios.json
python3 scripts/validate_project_settings.py <project-root>/.devbuddy/settings.yaml
python3 scripts/bootstrap_knowledge.py --project-root <project-root> --dry-run
python3 scripts/validate_knowledge.py --project-root <project-root>

ให้รัน bootstrap แบบ dry-run เพื่อเตรียม inventory ของ repository ที่ตรวจทานได้ และใช้ --apply หลังตรวจทานแล้วเท่านั้น โดยจะเขียนเฉพาะ Context.md กับ KnowledgeBase.md ไม่เขียนทับไฟล์เดิมที่มีเนื้อหา และไม่สร้าง typed canonical entity หรือ business policy ขึ้นเอง ตัว initializer จะวาง KnowledgeBase.md, core files อื่น, typed knowledge และ task ledger ไว้ใต้ <project-root>/.devbuddy/ โดยตรง หากใช้ external vault ให้ใช้ --root <approved-external-memory-root> --source-root <project-root> แล้วตรวจด้วย python3 scripts/validate_knowledge.py --root <approved-external-memory-root>

หลังติดตั้ง ให้ยืนยันว่า /devbuddy ชี้มาที่ skill นี้ และ agent devbuddy-* ปรากฏในรายชื่อ agent จากนั้นลองสั่งงานแบบอ่านอย่างเดียวด้วย bare task เช่น /devbuddy inspect the repository and report current delivery risks แล้วตรวจว่า Orchestrator สร้าง task ledger บันทึกคู่ model และ effort พร้อมเหตุผล เลือกกราฟ role และส่งงานให้ subagent ผู้เชี่ยวชาญจริง

ถ้ายังไม่มีไฟล์ตั้งค่าโครงการ ระบบควรหยุดที่สถานะ waiting_user นี่คือพฤติกรรมที่ถูกต้อง ไม่ใช่ข้อผิดพลาด

การอัปเกรด

  1. แก้ข้อกำหนดกลางที่ devbuddy-source-of-truth ก่อนเสมอ แล้วจึงซิงก์รายการใน checklist
  2. เมื่อแก้ไขบทบาทใด ให้สร้างไฟล์ subagent ใหม่ด้วย python3 scripts/generate_agents.py และตรวจสอบด้วย --check
  3. รันสคริปต์ตรวจสอบอีกครั้ง ปรับปรุงคู่มือทั้งสองภาษา แล้วรันตัวติดตั้งซ้ำ ตัวติดตั้งจะเขียนทับเฉพาะไฟล์ของตัวเอง

การแก้ปัญหา

อาการสาเหตุและวิธีแก้
เรียก /devbuddy แล้วไม่รู้จักยังไม่ได้ติดตั้ง หรือเซสชันเปิดอยู่ก่อนติดตั้ง ตรวจไฟล์ ~/.claude/skills/devbuddy/SKILL.md แล้วเริ่มเซสชันใหม่
มี skill ชื่อ devbuddy ตัวอื่นตอบแทนมี skill ชื่อซ้ำกันสองตัว ให้ลบหรือเปลี่ยนชื่อตัวที่ไม่ต้องการ ระบบจะไม่เดาว่าคุณหมายถึงตัวไหน
ส่งงานแล้วหยุดที่ waiting_user ทันทีส่วนใหญ่มาจาก .devbuddy/settings.yaml ที่ขาดหายหรือไม่ถูกต้อง ให้รัน validate_project_settings.py แล้วอ่านชื่อฟิลด์ที่รายงาน
ไม่พบ devbuddy-<role>-<effort>ยังไม่ได้ติดตั้ง agent หรือระดับ effort นั้นไม่ได้รับอนุญาตสำหรับบทบาทและความเสี่ยงนั้น ให้รันตัวติดตั้งใหม่และตรวจ approved_effort_levels
ยืนยันระดับ effort ที่ใช้จริงไม่ได้ให้ถือว่าการส่งงานนั้นถูกบล็อก การเลือกที่ตรวจสอบไม่ได้ไม่ถือว่าสำเร็จ
สคริปต์ตรวจสอบรันไม่ได้ตรวจว่ามี Python 3 ในเครื่อง อย่าติดตั้งอะไรโดยไม่ได้ตัดสินใจเอง เพราะสคริปต์ไม่ต้องใช้แพ็กเกจเพิ่ม

อย่าใช้โหมดข้ามการขอสิทธิ์เพื่อเลี่ยงด่านอนุมัติของ DevBuddy หากสิทธิ์ การเข้าถึงเครื่องมือ หรือ model ที่ใช้ได้ในเครื่องคุณต่างจากนโยบายกลาง ให้มาร์ครายการใน checklist ว่ายังไม่สมบูรณ์พร้อมบันทึกหมายเหตุ แทนการหาทางเลี่ยง
